├─ 开发工具/

## 检查脚本分类索引

`开发工具/检查/` 下脚本按用途分类（脚本文件本身仍平铺，避免破坏 `__dirname/../..` 相对路径假设）：

- **核心检查**（run.js 引入）：`_smoke_test.js`、`_verify_all.js`、`_verify_save_safe.js`、`_audit_announcement.js`、`_verify_scenes.js`、`_verify_feedback_ui.js`、`_verify_ui_layout.js`、`_verify_newgame_confirm.js`、`_verify_camp_panel.js`。
- **专项验证**（`_verify_*`，可独立运行）：地图、移动、存档、神弓、晾肉架、场景、设置、冻结、图鉴等。
- **诊断/只读**（不据此删内容）：`_dead_code.js`、`_audit_sources.js`、`_balance_review.js`、`_check_*`、`_rare_scan.js`、`_diag_food.js`、`_calc_skill_days.js`。
- **历史问题诊断**（`_debug_*`）：多为一次性定位，现多只读或产出到 `_out/`。
- **一次性迁移/生成**：`_oneoff_mailguide.js`、`_sweep_dev.js`、`_preview_anim.js`、`_anim_stats.py` 等。

生成图片输出统一写到 `开发工具/检查/_out/<专题>/`；旧的就地输出目录（`_*_out/`、`_*_shots/`）已迁至 `开发工具/检查/_out/历史输出/` 并在 `.gitignore` 加了防复发规则。

## 发布流程

作者明确要求打包时才执行。版本由 index.html 的 BUILD_VER 唯一定义，九处资源缓存参数必须与完整构建号一致（六个 JS、三张 CSS）。

```powershell
# 示例版本；必须使用作者本次决定的实际版本
node 开发工具/生成/_bump_version.js v1.09
node 回归测试/run.js --browser
python -X utf8 开发工具/打包/_pack.py --check
python -X utf8 开发工具/打包/_pack.py
python -X utf8 开发工具/检查/_verify_zip.py
```

包内顶层固定为 `guyuyizhang/`。打包默认拒绝覆盖同版本文件；确定需要覆盖时显式加 `--force`。终检逐字节比较全部源码与包内文件，并拒绝重复、缺失和多余条目；可传入其他 zip 路径，但仍与当前源码比较，不是历史版本功能测试。打包不等于上传发布。

## 已知经验

- UI 作用域问题可能通过语法检查，却在切场景时崩溃；必须运行场景浏览器检查。
- 图标文件与 ui.js 图标登记表要一致，兼顾既有彩色图标规则。
- 地图热点固定在地图坐标，滚出画面时隐藏；改坐标后检查相邻标签重叠。
- 一次性探索奖励由实际领奖回调登记，避免先标记完成导致漏奖。
- 静态死代码扫描存在动态引用和数据类型误报，不直接据此删内容。

低成本外部只读复核的调用边界、凭据方式和本轮用量见 [低成本复核说明](文档/开发协作/低成本复核说明.md)。

UI职责：`css/style.css` 管理基础主题/场景/通用控件；`css/panels.css` 管理制造、背包、装备共享面板布局；`js/ui.js` 内 `layoutWorkModal` 提供共用壳，事件绑定仍在原 `bindModal`。
