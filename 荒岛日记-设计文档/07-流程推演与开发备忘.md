# 07 流程推演与开发备忘

> 本篇回答一个问题：**这份设计真的跑得通吗？**
> 用逐日推演把五条因果链走一遍，每一步都检查"解锁条件的前置材料是否已可获得"。

## 7.1 推演假设（数值基准）

- 采集一次 15min：木材×3 / 石头×3 / 竹子×3 / 藤蔓×2 / 黏土×3 / 铁矿石(深层)×3；
- 钓鱼 30min 鱼×2；战斗 30min；吃饭 30min；睡觉 8h（草床）；
- 每天清醒 16h = 960min；本推演每天活动量 7~11h，全部留有弹性 ✓。

**推演结论**：
1. 每个解锁物（瞭望台/船/高炉/海图…）的前置材料，都在上一行已获得——无死锁 ✓；
2. 铁器时代从 D6 起步，靠的是 D5 交易的铁锭×4——**交易系统与装备链硬咬合** ✓；
3. 每天活动 6~11 小时 < 16 小时清醒时间——**时间预算成立** ✓；
4. 三条结局线在 D26 后收束，简单难度 25~35 天通关与推演一致 ✓。

## 7.3 数据模型（5 张表，开发直接照做）

| 表 | 关键字段 |
|---|---|
| 场景表 | id、名称、箭头坐标、距离分、地形分、解锁条件、赶路耗时、交互点列表 |
| 物品表 | id、名称、分类(原料/工具/武器/防具/食物/药品/建材/货币)、保鲜期、堆叠上限 |
| 配方表 | id、产物、材料清单、工位(工作台/熔炉/烟熏炉/织布机…)、耗时、解锁条件(经验等级/图纸) |
| 敌人表 | id、名称、区域、HP/攻/防/速、特性、掉落表、出现条件(昼夜) |
| 事件表 | id、类型(剧情/随机)、触发条件(天数/场景/概率)、前置条件、结果选项、奖励 |

存档字段：当前天数时刻、天气、季节、瞭望台等级、建筑等级、家具列表、背包、生存数值、
技能经验、货币、声望、事件完成标记、关键道具、日记文本。

## 7.7 给未来实现 AI 的三条硬约束

1. **改动任何数值前，先跑 7.2 推演**——推演通过才允许改；
2. **新增内容必须通过三问校验**，并写清消费者是谁；
3. **禁止新增第六种异常状态、第十八种敌人、第十三个场景**（除非重做整体平衡推演）。
