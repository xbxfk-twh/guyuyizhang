# 云存档（TapTap 云存档 v4）接入说明

> 作者 2026-09-18 问："能不能搞一个超级稳定的存档版本？" —— 下面是查证结果 + 已经做进游戏的东西。

## 一、查证到的官方规则（developer.taptap.cn）

来源：`minigameapidoc/dev/api/open-api/cloudsave/tap.getCloudSaveManager/`、
`.../CloudSaveManager.*`、`docs/sdk/tap-cloudsave/features/`（2026-09-18 抓取）

| 项 | 结果 |
| --- | --- |
| 谁能用 | **TapTap 小游戏**（基础库 2.0.0+）；Android / iOS / PC 走 TapTap 登录 SDK |
| 入口 | `tap.getCloudSaveManager()` —— 全局单例 |
| 方法 | `createArchive` 建、`updateArchive` 更新、`getArchiveList` 列、`getArchiveData` 下载、`getArchiveCover` 封面、`deleteArchive` 删 |
| 文件上限 | 单个存档 **10MB**、封面 512KB |
| 数量上限 | 单玩家单游戏 **100 个存档 / 100MB** |
| **频次** | **createArchive / updateArchive 一分钟最多一次**（错误码 400001） |
| 存档名 | 60 字节内、**不允许汉字**、不许空 |
| 上传前置 | 先用 `tap.getFileSystemManager()` 把内容写成本地文件（`tap.env.USER_DATA_PATH/xxx.json`），再把路径交给 API |
| 适用前提 | **必须有 `window.tap`** —— 也就是说游戏要跑在 TapTap 的小游戏容器里；用电脑浏览器直接开 `index.html` 时没有这层 |

## 二、已经做进游戏的三层存档（本地 + cookie + 云）

`js/game.js` 里新增一段"云存档"，和原来的本地/cookie 存档组成三层：

1. **本地 localStorage**（原有）—— 每次保存实时写。
2. **cookie 镜像**（原有）—— 平台清 localStorage 时靠它救回来。
3. **TapTap 云端**（新增）—— 自动同步，规则：
   - **上传节流**：官方一分钟一次，我们做成 **65 秒一次 + 只传最新一份**（有改动就记 `dirty`，到点自动补传），绝不会顶到频次上限。
   - **没进度不上传**：还没开局时不上传，省下那"一分钟一次"的配额。
   - **下载只认更新的**：启动时拉云端 → 只有云端 `savedAt` **比本地新**、且内容能解析、带 day 字段，才覆盖本地；旧云档绝不覆盖新本地档。
   - **失败不阻塞**：网络/权限/限额任何一步出错，只记一行状态，游戏照常玩。
   - **没有 tap 时静默关闭**：电脑浏览器、直接开网页都不受影响。
4. 设置面板新增一行「云存档」：显示当前状态、最近同步时间，支持时还有「立刻传到云端」按钮。

用假 TapTap 环境（模拟 `window.tap` + 文件系统 + 云）跑过完整流程：
上传 1 次 ✓、一分钟内重复保存被节流 ✓、换设备从云端恢复"第 7 天" ✓、旧云档不覆盖新本地档 ✓、
没有 tap 时全部静默跳过 ✓。

## 三、要真正跑起来，需要作者做两件事

1. **确认发布形态**：这个游戏在 TapTap 上是「**小游戏**」类型吗？
   - 是 → 云存档 API 直接可用（小游戏容器会注入 `window.tap`），我把打包产物给你，你上传即可。
   - 不是（普通网页 / APK）→ 云存档 API 用不了。要么改成小游戏发布，要么自己搭服务器（不推荐，成本高）。
2. **在 TapTap 后台开启云存档服务**：就是你给的那个页面
   `developer.taptap.cn/455373/app/921745/cloud-save-v4`（需要登录，我这边抓不到内容），
   按提示开通；小游戏一般还要确认基础库版本 ≥ 2.0.0。

## 五、它到底怎么生效（作者 2026-09-18 追问）

### 生效链条（四步缺一不可）

1. **游戏跑在 TapTap 小游戏容器里** → 容器才会注入 `window.tap`。用电脑浏览器 / 直接开 `index.html` / 某些"创意工坊外链"形态都没有它 → 云存档层**自动关闭**（本地存档照常）。
2. **后台开通了云存档服务**（就是那个 `cloud-save-v4` 页面）。
3. **玩家登录了 TapTap 账号** —— 云存档是**按账号**存的，换号登录看到的是另一个账号的档。
4. **至少成功上传过一次**：游戏里任何一次保存（`save()` / `metaSave()`）都会排队上传，但受"一分钟一次"限制，所以进游戏玩 1~2 分钟后才会真正上云第一份。

### 怎么验证它真的生效（只有你能做，5 分钟）

| 步骤 | 期望看到 |
| --- | --- |
| 在 TapTap 客户端里进游戏 → 设置 → 「云存档」 | 显示 **「云存档已就绪」/「已同步到云端」** + 一个最近同步时间 |
| 显示"这台设备没有云存档" | 容器没给 `tap` → 形态问题（要按小游戏形态发布） |
| 显示"列表读取失败/上传失败" | 后台服务没开 或 权限问题 |
| 玩到第 N 天 → 等 1~2 分钟 → 换另一台设备（或清掉本地数据）再进 | 自动恢复到第 N 天，日志里出现「【云存档】已从云端恢复进度（第 N 天）」 |

### 它**防不住**什么（这些别指望云存档）

- **首次上传之前的进度**：刚开局、还没上云就卸载 → 云端没有可恢复的东西（本地那份也一起没了）。
- **最后 1 分钟内的进度**：平台限制一分钟只能上传一次，那一小段可能只在本地/cookie 里。
- **玩家自己把存档改坏/删掉后再上传**：云端只存"最新一份"，坏档会被传上去（我们的上传只在本地写入成功后触发，且拉取时会校验天数，但不能 100% 免疫）。
- **TapTap 账号本身的变化**：换号、账号被封、平台清掉该账号的云存档。
- **TapTap 云存档服务自身的故障/下线**。

### 所以"只要 TapTap 不出问题，存档就不会消失"这句话

**基本对，但有两个前提**：① 游戏确实跑在小游戏容器里并且**云存档服务已开通**；② 玩家在丢进度之前**至少成功上云过一次**（也就是"玩了 1 分钟以上"）。

而且云存档**不是唯一防线**。真正的四层是：

| 层 | 防什么 | 依赖 |
| --- | --- | --- |
| 本地 localStorage | 日常写入 | 浏览器不清缓存 |
| cookie 镜像 | 平台只清 localStorage 时 | 平台不连 cookie 一起清 |
| **TapTap 云存档** | 换设备 / 卸载重装 / 清缓存 | 小游戏容器 + 后台已开通 + 已登录 |
| **导出存档码**（菜单 → 备份·读档） | **以上全挂也不怕** | 什么都没有——玩家自己存一串字符 |

所以公告里那句"隔一段时间导出一串存档码存好"不是客套话，它是**唯一不依赖任何平台**的保命手段。
