# 《孤屿遗章》双人试验与海底资源更新

2026-11-19。双人联机开发版包含独立房间存档、孤岛地图、共享箱和战斗。

## 打开双人联机

在仓库根目录用 Python 3.10 或更高版本启动。

```sh
python "开发工具/双人试验/server.py"
```

浏览器打开 http://127.0.0.1:8088/coop.html，或从游戏标题选「双人联机」。一方建房，另一方输入八位房间码。同机用两个浏览器配置。两台设备在同一 Wi-Fi 时加 `--host 0.0.0.0`，队友打开主机局域网地址。房间记录由 SQLite 保存。客户端保存各房间的座位凭据，退出到大厅后从「联机存档」选房间继续。房间码用于邀请，原座位仍由本机保存的凭据认领。

- 双人在线时，没人行动、一人行动、两人行动分别按每秒 0.2、3、10 游戏分钟运行。单人在线只有慢速 0.2 和行动时的 10。无人在线时暂停。掉线到期后暂停离线玩家的行动，回来按剩余进度接着做。
- 陆路使用正式地图基础距离。从营地到山洞 35 游戏分钟，双在线单人赶路约 11.7 秒，单在线约 3.5 秒。双人若同时开工，先结束的人退出加速档。批量制作绷带每条 15 游戏分钟，最多 20 条，开工时一次扣足材料。
- 预计还需等超过 25 秒才显示「看个广告吧」。完整播放后由游戏宿主向现有钱包入账 3–6 星之点或广告币。符合等待条件时可再看，无每日或每行动次数上限。跳过没有奖励。写盘失败可重试入账，已有单机商城广告计次独立。
- 大地图左上显示队友所在地点和当前行动，蓝、红箭头标记最近到达的位置。邀请限双方在线、空闲且同在树林或山洞。接受后自由选目标，分别结算攻击和包扎冷却。分开探索时可同时进入各自的单人战斗。
- 每名玩家的普攻间隔为 1.5 现实秒。狼、野猪、蝙蝠群各自按节奏反击，双人联手时增加敌人数量。离线和倒下者不再承伤，两名参战者都离线时敌人暂停，回来不补打。包扎各自冷却 4 秒，胜利时仍站着的玩家分别获得战利品。
- 营地共享箱串行结算存取。房间服务结算行动、战斗和库存。当前联机内容覆盖五处孤岛地点，完整单机剧情、昼夜生存数值和海底地图尚在单机。

## 双人计时示例

A 从营地出发去山洞，B 同时做一条绷带。前 1.5 秒共同推进 15 分钟，B 做完。两人都保持在线时，A 剩余的 20 分钟按每秒 3 分钟结算，总共约 8.2 秒到达。

## 公网入口

客户端使用 `https://guyuyizhang.top:8443/coop/v1`。将服务源码放入 `/opt/guyu-coop/server.py`，使用独立服务账号 `guyu-coop`。以下单元让房间数据库落在 `/var/lib/guyu-coop/`，服务端只监听回环，并由现有官网 HTTPS 接入。

```ini
[Unit]
Description=Guyu cooperative room service
After=network.target

[Service]
User=guyu-coop
StateDirectory=guyu-coop
ExecStart=/usr/bin/python3 /opt/guyu-coop/server.py --api-only --port 18083 --db /var/lib/guyu-coop/rooms.sqlite3
Restart=on-failure
NoNewPrivileges=true

[Install]
WantedBy=multi-user.target
```

在 Nginx 的 `http` 块加入速率区。在现有官网的 8443 `server` 块加入以下路径，沿用官网 HTTPS 证书。

```nginx
# http
limit_req_zone $binary_remote_addr zone=guyu_coop:10m rate=10r/s;

# 官网的 8443 server
location = /coop/v1 {
    limit_req zone=guyu_coop burst=20 nodelay;
    limit_req_status 429;
    client_max_body_size 4k;
    proxy_connect_timeout 2s;
    proxy_read_timeout 8s;
    proxy_pass http://127.0.0.1:18083;
}
```

运行 `nginx -t` 后重载既有 HTTPS 服务。用两台设备经公网建房、加入、断线重连并模拟服务器重启。数据库备份使用 SQLite 在线备份接口，配合现有备份计划。默认容量为 1 万个房间，应根据活跃规模与存档保留策略调整。空闲客户端约 3 秒轮询一次，行动及战斗期间约 0.75 秒一次。客户端修改请求超时后重试一次，服务端按操作编号去重。

联机服务不处理游戏钱包。Android 或 TapTap 宿主负责展示激励广告并入账。部署房间接口不会启用普通浏览器广告。

## 复核

本地压测用 40 间房、80 名客户端每秒各发一次状态请求，每轮 480 次全部成功。两轮应用侧 p95 约 5 至 8 毫秒。结果不包含公网时延、实际主机性能及 Nginx。接续版已用两个独立 Chrome 验证手机尺寸与模拟宿主广告。公网部署及宿主真广告待验证。
