## 2. 本轮目标

把纵向弹窗改成独立的「版画战场＋固定操作栏」：敌人可见、目标明确、手机一屏可操作、每次行动结果可读。保留现有战斗结算和平衡，先改善表现和交互。

不新增自动战斗、实时反应判定、连招、自由走位、每个敌人独立距离、玩家角色骨骼动画。本轮不新增独立“移动”行动，保留既有“攻击会先靠近”的规则；不能因为视觉上的距离条而改变规则。

## 3. 当前代码事实（实现前复核）

- `renderCombat()`：开战建立战斗弹窗，更新由 `updateCombat()` 处理；结束先展示最终敌人血量，再延迟一秒关场。`fightSeq` 已用于防止上一场延迟关闭下一场。
- 敌人数组在 `C.enemies`；图片可从 `ENEMIES[e.id].img` 查，不要假设运行时敌人实例直接带 img。
- 现在多敌人操作为先点行动、再点血条，临时状态为 `PENDING_ACT`。
- 行动接口是 `Game.fightAction(act, ti)`；普攻、射击、投掷、重击、必中需目标，横扫是全体，防御/道具/逃跑不需目标。具体合法行动以代码为准。
- 现有 `combatActionInfo`、`combatAccuracy`、`heavyInfo`、`sureInfo`、`sweepInfo` 等查询可复用；不要在 UI 再写一套命中、冷却、弹药优先级、射程和体耗公式。
- 防御保护本次全部来袭；每场战斗最多两次道具，投掷每场一次。已有冷却、弹药和武器限制全部保留。
- 目前距离已在状态行显示，又重复写入日志；新版改成唯一常驻信息。

## 4. 布局和响应式

建议使用覆盖游戏区域的独立战斗面板，背景与主场景隔离；不能点穿、不能操作场景热点。按视觉四层组织：

1. **顶部状态栏**：遭遇名称／首领标记、玩家 HP 与体力数值、重要负面状态。展示回合标识必须沿用 C.round，不编造“下一轮所有敌人必攻击”的回合含义。
2. **战场**：低对比度当前场景背景，上方/中间横向排列敌人，敌人各有画像、编号、血条和意图。优先只画敌人，不强行给玩家新增形象；玩家状态栏足以表示自身。
3. **信息带**：选中目标、距离、此目标的命中/靠近提示，最近行动摘要；完整战况用展开按钮。
4. **固定底部操作区**：攻击、防御、战技、道具、逃跑。装备远程时增加射击入口。

### 尺寸规则

- 手机横屏 844×390、667×375：根面板为固定网格，顶部约 40–48px，战场占剩余空间，信息带约 36–48px，操作区约 88–104px；这是预算而非硬编码绝对值，按内容测量调整。
- 普通操作按钮触控区域至少 44×44px。操作栏最多两排，不能让名字/冷却解释把按钮无限撑宽或压出屏幕。
- 桌面 1920×900：战场主体居中，操作区限制最大宽度，避免按钮散到两端；保持同一操作逻辑。
- 补测竖屏 390×844：战场和操作区适配较窄宽度，信息可换行，底栏仍可达；不新增强制横屏阻挡。
- 全局不横向溢出，不用滚整个战斗面板才能攻击、喝药或逃跑。长战况只在自身列表内滚动。
- 安全区采用 `env(safe-area-inset-*)`。保持 iOS/WebView 可点击；尽量原地更新血条，不每次重建全树。

## 5. 敌人展示和选目标

- 一只敌人居中放大；2–3只并排；4–5只缩小为等宽卡，手机窄屏允许卡内头像较小，血量和选中态优先。超出已知数量时提供紧凑列表兜底，不隐藏目标。
- 同种敌人标号如「狼①、狼②」，便于摘要明确击中谁；编号在同一场保持稳定。
- 每个活目标是可点击/键盘可聚焦的按钮，画像、名字和血条均可选中。选中态用粗墨框＋下方小箭头＋“目标”文字，不只靠颜色。
- **先选目标，再点动作**。选择只改变 UI 状态，不推进战斗、不扣体力、不消耗道具。单敌人自动选中；多敌人首次默认第一个活目标，并明确突出显示。
- 同一目标只要活着，就保持选中；不要在每次更新或鼠标悬停时自动换目标。悬停只提供轻微反馈，不能改选择。
- 目标死亡后，先展示击杀反馈，再自动选下一个活目标，并短提示“目标已切换：狼②”。选中目标身份不能只用数组下标：敌人死亡后数组会过滤，下标会变化。优先 UI WeakMap 给敌人对象分配场内 ID；若实现发现对象会重建，再采用不影响持久化的稳定标识。调用行动前用当前数组解析真实 ti，验证仍活着。
- 战斗开始、结束、读档重建和连续下一波时重置场内选择及映射，不能把上一场目标带进新战斗。

## 6. 操作栏

### 常驻操作

- **攻击**：使用现有 Game.combatActionInfo 判断；需要靠近时按钮明确为“靠近目标”，说明“本次先靠近”，不能误写成造成伤害。不要把靠近时的普攻灰掉。
- **射击**：有远程武器时显示；无弹药可灰置并写“缺箭矢/缺源能子弹”。沿用实际武器选择和弹药优先级，不能 UI 显示一把、副手实际射另一把。
- **防御**：说明“防护本次全部来袭”，沿用现有结算。
- **战技**：打开底栏上方的紧凑面板，列出实际可见的重击/必中/横扫/投掷。未学习技能不显示；已学习但冷却等不可用则显示短原因。若没有任何相关动作，可省略入口。横扫明确是全体，不要求切目标。
- **道具**：显示本场剩余次数；沿用现有药品筛选与战斗用药规则。不能把所有食物/普通背包物品误变成战斗可用道具。
- **逃跑**：与攻击隔开，采用次要按钮。保留原失败代价；不增加每次逃跑二次确认，避免危急时多点一次。

### 详细信息

按钮正文优先动作名，辅助行最多一条短信息。被禁用原因在面板内可读，不能只依赖 hover/title。命中率针对当前选中敌人计算。

首版必须显示当前 HP/体力、弹药和冷却。体耗、预计伤害、逃跑成功率只有在引擎已有可信查询时才显示；若需要新增查询，必须纯函数、无随机数/状态改变并经测试。不承诺UI无法可靠预测的精确伤害。

### 面板规则

战技、道具、战况在战斗内部打开，不能调用普通弹窗把整场 DOM 替换掉。关闭子面板回到原战场、原选中目标；打开/关闭不算行动、不触发敌人攻击。长列表可内部滚动，顶部固定返回入口。道具无可用时明确提示。

## 7. 画面和反馈

- 保持黑白版画、暖灰纸面；背景压低对比，敌人轮廓和选中态清楚。玩家 HP 危急/敌人蓄力可用少量既有危险强调色，但信息仍用图形与文字表达。灵灰/既有彩色皮肤例外继续沿用。
- 优先复用敌人和场景图片。场景取当前已解析资源/当前皮肤，海底区域及缺图有中性纸纹兜底。不要只把 S.scene 当路径拼接，可能是地图容器。
- 画像若有白底，采用版画卡/纸片风格；不要强行抠图或滤镜把已有彩色素材毁掉。首领适度放大并加版画边框，不另做覆盖整屏的过场。
- 普通命中：目标轻微后退，浮出数值；闪避/未命中显示文字；格挡显示短盾形墨印；暴击加短斩击墨痕。普通效果约 200–350ms，不让玩家每次等一秒。
- 反馈必须来自真实结算。不要解析中文日志猜伤害对象/数值来做可靠战斗反馈。优先比较行动前后状态；如要区分暴击、格挡等，允许引擎新增**仅运行期**的结构化表现事件，记录目标ID、实际伤害、结果类型与顺序。事件不改变随机调用次数、战斗时间或存档语义，不进入主存档和日出快照。
- 多敌连击按事件顺序简短表现，原结算先一次完成；表现期间挡住额外输入。选择目标本身不触发动画。减少动效模式只更新数值和短文字、不震屏，遵从 prefers-reduced-motion。
- 保留现有战斗音效映射，避免旧日志音效与新事件重复播放。

## 8. 战况和结束

- 默认只显示最近两三条摘要，完整 C.log 保留且可查看；敌人简介移到敌人详情小入口，不占每回合常驻空间。重要意图（蓄力、下击双倍、猛击后的防御0、掩护、流血、中毒）直接在敌人卡显示，过长可展开。
- 意图必须解释现有状态，不把“蓄力”推断成未实现的精确未来动作预测。
- 本场最后一击先显示血量0，再给约0.6–1秒结束反馈。首版沿用现有1秒更稳妥。
- 胜利短条显示“击败敌人”，若要展示掉落必须从引擎实际掉落结果读取；拿不到结构化结果时使用原日志，不能另随机/重复发物品。
- 普通击杀与整场结束分别处理；逃跑成功、死亡走各自原流程。死亡仍进入既有结算/复活界面，连续夜袭/下一波不得被旧回调关闭。

## 9. 状态和实现约束

- 战斗操作控制状态建议 `idle → resolving → presenting → idle/ended`。一次点击最多调用一次 Game.fightAction；连点、双击、触屏重复事件、键盘长按不能重复扣体力或弹药。
- 只用一个事件入口处理一次动作，禁止 touchstart 和 click 各执行一次。动画回调加 fightSeq/实例令牌校验，战斗已结束/对象变化就丢弃。
- 引擎拒绝行动时给明确提示并立即恢复可操作，不能永久锁按钮；异常/缺图不阻塞战斗。
- UI 选择、展开面板、动画锁及场内编号为运行期状态，不新增存档字段。战斗存档继续按原兼容规则，不保存 DOM、定时器或函数。
- 替换 PENDING_ACT 时检索全部动态引用、测试和工具；保留旧选择器时让它们真正对应可操作元素，不能造不可见“测试专用”节点。
- 不在 UI 用覆盖 C.enemies、改血量等方式驱动动画。如加表现事件应采用独立暂存结构，记录完清理。

## 10. 分步实施（同一对话顺序完成）

1. 基线：阅读源码/CSS和现有战斗专项，运行核心测试，记录单敌、多敌、首领手机截图。确认实际 scene/敌人资源查询与行动返回值。
2. 布局：新增战场布局，固定状态/操作区，各敌人画像和血条，一屏可达；先保持旧结算，完成三种横屏/桌面及竖屏截图检查。
3. 操作：完成稳定目标选择、战技/道具子面板、目标死亡切换、防连点和禁用原因；验证实际攻击/射击和道具。
4. 表现：接入短动画、行动摘要、意图和结束反馈；必要时添加最小结构化表现事件，确认不会增加随机调用或结算次数。
5. 回归：完成下述验收，更新维护现状并交付截图和已知限制。不要为了赶进度只交布局，作者的目标同时包括画面与操作。

## 11. 验收标准

### 布局与交互

- 844×390、667×375、1920×900、390×844：攻击、防御、道具、逃跑无需滚整个窗口可点；无横向溢出、遮挡、背景点击穿透。五敌时所有目标可选。
- 单敌、多狼、五敌、首领、海底敌人、缺图兜底均检查实图；每种图片与当前敌人匹配。
- 先选目标后攻击，连打保持目标；选第二只狼击杀后剩余目标不串号、不误打；横扫不吃选中限制。
- 未学技能、缺弹药、冷却中、投掷已用、道具两次用完给出正确禁用说明。靠近行动可执行且没有虚构伤害。
- 战技/道具/战况开合不触发行动，关闭后状态和选择保留；手机不用悬停也能看规则。
- 连点、双击、键盘重复输入和动画期间点击只结算一次；敌人反击、体耗、弹药、耐久与旧引擎相同。
- 最后一击归零后退出，死亡复活/逃跑/连续下一波正确；减少动效可用，旧回调不串场。

### 数值与存档

- 尽量使用相同随机序列对比关键行动前后的 HP、体力、弹药、耐久、冷却、C.round和敌人状态，确保表现改造不改变战斗规则。
- 独立测试存储/浏览器配置，不读写真实玩家存档、不清玩家缓存。
- `node 回归测试/run.js`；`node 回归测试/run.js --browser`；按实际改动扩充战斗专项。旧测试交互确已改变时更新操作路径，保留行为断言，不放宽断言掩盖问题。
- 检查 JS 语法、差异格式和实际手机/桌面截图。报告真实测试结果及复验情况。
