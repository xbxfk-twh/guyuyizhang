# 战斗界面改版实现记录

按《战斗界面改版实施方案_20261005.md》实施。源码为 `孤屿遗章-游戏 - 发布/`，本轮没有改版本、打包或发布。

- 独立暖灰版画战场覆盖游戏画面；当前场景资源作为低对比背景，顶栏显示真实回合、生命、体力和状态。操作栏固定，桌面居中；窄竖屏两排，战斗期间不显示原有横屏遮罩。
- 一到五只敌人各自显示真实画像、稳定场内编号、血量和意图。超过五只沿用透明立绘并在战场内部横向滚动。缺图使用文字印记；召唤物复用对应怪物画像。
- 先选目标再行动；选目标与悬停不结算，活目标保持选择，死亡目标先显示归零和打击反馈，再切换下一个活目标。目标对象用运行期 WeakMap 编号，调用引擎时重新解析下标。
- 攻击不足射程显示“靠近目标”；射击按主副手实际远程武器与弹药优先级显示，无弹药仍显示禁用原因。防御、逃跑保留原规则。重击、必中、横扫、投掷在战技子面板中，冷却与原因沿用引擎查询。
- 战斗道具与完整战况都在原战场内部展开，列表自行滚动，关闭保持目标。道具沿用药品筛选与每场两次限制，没有新增食物或普通物品可用权限。
- 引擎新增 WeakMap 结构化表现事件，顺序记录命中、暴击、未命中、格挡、闪避、受到伤害、持续伤害与靠近。没有新增随机调用，事件不属于存档/日出快照。浮字和短后退来自真实事件；原日志音效映射保留，事件不重复播放音效。
- UI 结算/表现期间禁止重复动作，使用一个 click 入口，阻止键盘长按重复，令牌防止旧场定时器影响下一场。减少动效不震动。最后一击包括持续伤害清场均保留真实零血名单，再停一秒结束。
- 不增加移动行动、自动战斗、精确伤害预测或掉落副本，不改变出手时间表与战斗平衡。预计伤害、体耗和逃跑率未新增展示，因为现有查询没有统一可信口径。

验证使用独立 Chrome 配置及内存存储。新增 `battle-presentation.test.js` 以相同随机序列对照移除表现记录的引擎，比较生命、体力、弹药、耐久、冷却、回合、状态与随机调用次数，并验证存档无表现数据。`_verify_battle_board.js` 检查 667×375、844×390、1920×900、390×844 的真实界面与操作，截图在 `回归测试/_out/battle-*.png`。旧战斗专项更新为新子面板操作路径，保留实际伤害、冷却及迁移断言。

浏览器验证不等于 TapTap 真机验证；iOS/WKWebView 的实际触控与声音仍应由作者实机复验。

## 作者补充要求的完整改版（2026-10-05）

前轮只有战场结构与首领入口。本轮落实透明立绘、动画时序、左侧日志与战斗音乐，替代前轮敌人卡片式外观。没有改发布版本、打包或上传。

- 噩梦模式所有敌人生命/攻击固定按困难倍率1.3，不再给同阶梦魇叠加每20天2.5%的倍率；解锁阶数与遭遇概率仍随天数增加。首领入口保留海底深水圣殿、击败沉没之王后解锁、不限天数。
- 24张普通敌人及四位原首领通过内置imagegen去掉场景背景并保留版画主体，加入 `assets/img/battle-cutouts/`；七版梦魇直接使用已有透明图。原图片保留给图鉴等其他用途，24张RGBA的Alpha均有0与255，生成来源与提示词概要见 `../美术评稿/战斗透明素材_20261005.json`。
- 敌人直接站在当前场景背景上，横向排列，移除目标容器与图片边框，名称/血条基线一致。目标使用地面阴影与箭头提示，距离按 `.46+.54/(1+距离/24)` 缩放；记录真实移动端点，以360毫秒插值显示靠近。
- 生命置于左上角，战斗日志常驻左侧并滚动；关键伤害、暴击、恐吓、晕眩、分裂、掩护、治疗等用红/赭黄/青绿强调，日志先转义后着色。战场双线墨色边框、暖灰纸色与低饱和场景融合。
- 界面根据引擎实际事件顺序播放，同侧事件相隔230毫秒，移动另留360毫秒，切换玩家/敌方留完整1000毫秒。保留引擎原先手与速度累积，不按固定玩家先手编排。播放中血条沿事件变化、重要反馈进入左栏；播放完与引擎最终状态对齐。
- 敌方伤害显示半透明红色效果：咬合、爪痕、刀斩、枪弹、裂隙，根据攻击者类型选择。命中与敌方打击音也按播放时点触发。
- 战斗道具卡片飞向屏幕中央，带尾迹，520毫秒后碎裂，200毫秒后才实际使用。飞行期间不提前扣物品或触发药效，仍遵守每场两次上限。动画期间锁定输入，场次令牌防止旧动画影响新战斗；减少动效时跳过飞行与等待。
- 普通战112BPM，首领144BPM；沿用A小调和声，加入连续琶音、低音、鼓点及高帽，首领增加八度旋律和鼓点强度。保留三个声音开关和角色语音开关，不恢复已删除的试听入口及旧睡醒/传送声音。
- 首领不生成通用蓄力/掩护/猛击，并清掉旧战斗中的这类首领意图；小弟仍保留。小弟掩护能够保护首领，首领自己的专属恐吓、分裂等技能不受影响。
- 最后一击的零血量、动画及日志呈现后保留原一秒停顿，再退出战场/显示结局；新增表现数据均只存在运行期，不改变存档字段。

专项验证：同随机序列引擎对照与时间线30项、噩梦19项、音频49项通过。四档实际Chrome战场80项通过，包含飞行时未扣道具、重复点击仅消耗一次、实测双方打击间隔至少一秒、逼近动画中间帧连续放大、透明敌人无边框、生命/日志位置、末击与连续战斗、减少动效及键盘焦点。截图在 `回归测试/_out/battle-*.png`。全套验证结果以维护现状最新条目为准。

## 引擎选择判断

现有项目是HTML/CSS/JS、带Tap云存档与广告接入。推荐逐步用Phaser承担战场与场景动画，保留Game的数据、数值和存档接口；这是迁移量最小的方案。Phaser官方说明其为JavaScript/TypeScript的2D Web框架，支持桌面/手机浏览器的WebGL与Canvas： https://docs.phaser.io/phaser/getting-started/what-is-phaser 。

若作者更重视编辑器中拖放房屋、家具和动画时间轴，优先比较Cocos Creator；其可发布桌面和移动Web： https://docs.cocos.com/creator/3.8/manual/en/editor/publish/publish-web.html 。Godot也适合2D，但现有JS数据/SDK需要桥接；Web导出要求WebAssembly/WebGL2，Godot4的C#项目不能直接Web导出： https://docs.godotengine.org/en/stable/tutorials/export/exporting_for_web.html 。

判断：使用引擎会让场景编排、粒子和动画更方便，但不会自动解决数值、旧档兼容或Tap接口；不建议当前整项目重写到Unity/Unreal。先做独立战场演示、证明旧档与广告正常，再决定是否扩展迁移。本轮仅提出建议，未安装或迁移引擎。
