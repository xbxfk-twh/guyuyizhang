# 《孤屿遗章》全代码整体重构方案

状态：2026-10-18原始整体方案。作者于10月19日授权实施；当前细化批次、落地范围与验证见[精细实施计划与执行账本](全代码重构_精细实施计划_20261019.md)。下文规模与核查结果保留原日期基线，不当作全部迁移已完成。

## 1. 结论与目标

建议完成一次覆盖全部源码的结构重构：把玩法、存档、界面、素材、音频与平台能力分开，通过明确接口协作。保留当前已经确认的玩法和黑白版画表现，逐功能接替现有实现，最终撤掉两个巨型闭包及散落的重复逻辑。

完成目标是：规则有唯一归属、数据只有一个真实来源、每次操作只有一个结算入口、每个界面独立管理自己的交互，测试能够在移动代码之后继续验证玩法。

这不是再清几段注释，也不是仅把game.js剪成几个片段。一个功能迁出后，它的状态修改、规则、查询、界面接线与测试都应有明确归属，原来的对应实现必须退役。

## 3. 技术方向

继续使用原生HTML/CSS/JavaScript，保留无需前端构建工具即可运行的能力；当前重构不同时迁移游戏引擎、上React/Vue、改用一整套TypeScript构建链或新增云服务。

采用按游戏功能划分的模块。模块用明确的工厂参数接收依赖，由bootstrap统一组装；保留普通script运行方式以兼顾直接打开HTML与本地WebView。公共注册表只用于启动装配，功能内部不能靠它到处找其他服务，也不制造第二套通用框架。

对外临时保留Game、UI、AudioFX等兼容外观，供旧界面、安卓宿主和工具接入；迁出的功能只保留转发，不保留两套计算。等调用者都迁完，再移除不再使用的转发。

用JSDoc描述输入、输出、状态及错误类型。可以增加只在开发时运行的类型检查，但先不让游戏运行或APK构建依赖新的大型工具链。

## 5. 必须先立住的边界

### 5.1 状态只有一份

本局S与账号M继续保持原字段含义，先由StateStore统一持有。不另外维护一份“新库存”并靠同步维持一致。每个模块有字段归属表：库存管物品与批次，装备管槽位/实例引用，战斗管战斗状态，存档管写盘状态。

UI只能发操作和读查询结果。现有Game.S与metaState的可写引用在迁移期登记调用者，逐个收口；最终界面得到只读快照。不能一开始冻结旧引用导致现有界面崩溃，也不能完成时仍允许随处直接赋值。

室内拖动目前还在UI直接写roomLayout并保存，应改为明确的MoveFurniture/ResetLayout操作。设置与平台状态也使用各自入口。

### 5.2 一次操作只有一个执行路径

统一操作返回形态，例如成功/失败码、被修改的领域、结构化反馈；界面不靠中文reason判断业务分支。

一次即时操作按“校验 → 副本计算 → 必要的持久化 → 提交 → 反馈”执行。库存、账号与本局同时变化时沿用恢复日志，写入失败不扣钱、不吞物品。操作锁按操作ID覆盖真实重入，失败和取消必须释放。

移动遇袭、采集先战斗、批量/等待制作等跨步骤流程，明确记录阶段与可恢复续办信息。战斗动画结束只负责显示或解锁输入，不能再结算一遍掉落；恢复存档后也不能重复领取。

不是所有按钮都立刻写六个存储键：保留既有自动保存节奏，区分内存操作和必须即时落盘的库存/账号事务，避免重构造成卡顿。

### 5.3 查询不偷偷修改游戏

容量、候选食物、可制作数量、工具资格和伤害预览都读同一状态快照，不消耗时间、随机数、耐久或物品。需要结算的保鲜/到期效果在操作、时间推进或读档边界完成，再提供查询快照。

同一份规则同时供预览和实际执行使用，执行时重新验证当前状态，避免预览可做但点击失败或扣错。

### 5.4 状态限制集中表达

建立结构化资格检查：是否在当地营地、是否处于真实战斗、是否有未完成操作、是否死亡、是否具备远程仓库权限。操作入口据此判断，UI展示同一结果。

对“营地里说战斗中”“能打开装备却不能更换”等问题，区分玩家所在位置、当前战斗、活动步骤和界面暂停；提供开发诊断信息及读档修复，不用盲目清空combat强行解锁。

### 5.5 时间与随机可复现

时间推进集中在一个调度器，逐小时/逐日效果按明确顺序调用。保留后台挂起、面板暂停、提灯累计磨损、跨日及水下消耗口径。

随机源与现实时间都可注入。等价迁移的前后版本使用相同种子与输入，比较结果和随机数消耗，防止仅因多画了一次预览就改变战斗或掉落。

### 5.6 文案、声音和动画只负责反馈

玩法产出结构化反馈，由日志、动画和音频分别消费；它们不能修改战利品、回血或判定通关。只用于表现的动画对象不写进存档。

日志保留类型、角色/物品ID与数值。历史纯文本日志继续显示；新日志按当前语言格式化。吸血等效果只有实际获得回复时才产出成功反馈。

## 6. 各领域怎样重构

| 领域 | 最终归属与要求 |
| --- | --- |
| 物品与配方数据 | 统一定义与引用校验；物品/配方/敌人/任务ID不随显示名称改动；数据加载不再暗中原地修改另一份表 |
| 库存/保鲜 | 统一容器适配、堆叠、来源权限、临期扣除、实际搬运；保存原批次和每件装备当前/最大耐久，自动存入与一键存入共用策略 |
| 装备/工具 | 装备槽、两手约束、背包容量、手动空槽、自动选工具和实际磨损来源统一；不靠物品名正则推断类型 |
| 制作/建造 | 预览与执行共用配方解析和条件检查；单次/批量共用成本、耗时、余数和产出；房屋/家具/海底设施由各自数据描述 |
| 时间/生存/食之包 | 分离推进时钟、小时效果和各项生存规则；食之包三组选项通过同一安全筛选与来源访问，不再在UI重算资格 |
| 场景/采集 | 旅行、抵达、遇袭、采集和战后续办明确分段；长按只查询；自动工具、收益余数与每日次数都可重放验证 |
| 战斗 | 分开合法动作、行动顺序、距离移动、命中/格挡/闪避/暴击、实际伤害与吸血、状态/首领机制、结算；先保持现有结算顺序 |
| 天赋/成长 | 统一技能前置、互斥、费用、遗忘、数值计算与升级预览；把散落加成钩子收为有来源的效果列表 |
| 交易/账号 | 价格、交易、邮箱领取与账号钱包分清；收据、跨局资产与防重复补足集中处理；不可为精简而删去对账保护 |
| 剧情/引导 | 明确任务条件、触发、奖励和下一步；新增文本与流程由稳定ID引用。保留现有结局、解锁与配音，不混入新的剧情重写 |
| 皮肤/素材 | 一个资源解析入口处理黑白/彩色/限定例外与回退；画面锚点、阴影与裁切元数据有归属，先不重命名或批量删除图文件 |

战斗拆分时尤其冻结：会心概率、双持攻速、首轮横扫、残血实际吸血、格挡先于独立闪避、首领与随从意图、远程距离、最后一击0血显示与结算时机。结构重构期间不顺便调平衡。

## 7. 界面、CSS与本地化

面板改为单一注册表：每个面板登记render/bind/dispose、暂停原因、返回位置与刷新策略。移除showModal分支、bindModal大段绑定、TIME_FREEZE_PANELS和返回键名单各维护一份的情况。

公共交互组件统一管理点击/长按/拖动、防穿透、数量输入、焦点、取消和监听清理；反复开关面板不得增加监听或重复执行。手机触摸是验收入口，不以程序化click代替全部操作。

背包搬运只更新受影响的物品、容量与选择状态；场景淡入只在场景切换时播放。镜头、背景、精灵、热点和命中区域共用一个坐标变换，保留原热点位置与滑动行为，避免热区和画面漂移。

CSS按基础变量、共用组件和功能作用域收拢。先拍下现有截图，按规则实际归属迁移，逐个移除重复覆盖；不批量删除!important。中文/英文与窄横屏都验收，图标、字号、间距、触控范围和黑白基调使用统一变量。

本地化逐步改为稳定文本ID及插值，替代新增中文句子后再追加全文替换。每个已迁移界面使用显式翻译；旧DOM替换只留在尚未迁移区域，避免双重翻译。全部功能覆盖并验证后再停用全局MutationObserver。既有存档/兑换码/物品ID不翻译，历史日志单独兼容。

## 8. 存档兼容的最终安排

新增独立的saveSchemaVersion、profileSchemaVersion，和发行版1.13分开。先把现有字段视为当前格式，新增版本标识及迁移登记，不在重构初期同时改变整套库存数据模型。

旧档在读入时执行有顺序、可重复验证的迁移，成功保存后才算迁移完成。主档、滚动备份、账号备份、存档槽、导入码、日出快照、抢救恢复共用入口；嵌套快照也必须纳入识别，不能只标外层已迁移。

历史迁移归入独立目录；正常采集/战斗只处理当前规则。已有裁缝台权利、仓库档位、旧技能折算、图纸知识与补差收据继续有效。跨局资产补足/兑换收据属于当前安全规则，不能因写着“旧档”就删除。

兼容代码的删除条件是：明确无调用者且不再需要该输入格式，或已决定停止支持并有转换通道。不能用存档v:1猜发行版，也不能以“现在能运行”证明备份能恢复。此次计划不以断掉老存档来换取表面简短。

## 9. 音频、资源、安卓与打包

保留音频现有内容，拆分音频策略、播放驱动与语音目录；统一宿主暂停、玩家静音、战斗/首领音乐切换与音效并发限制。音量与解锁播放处理不进入业务规则。

资源清单覆盖图标、场景、皮肤变体、动画和音频，登记存在性、引用与必要的来源许可。删除素材需同时查数据引用、代码拼接路径、皮肤解析和工具使用，不能仅靠静态未引用扫描。

平台层统一提供下载存档/打开文件/生命周期/返回等能力；安卓保持固定来源与固定命令白名单，不扩大通用桥或file/content访问权限。包名、签名、本地资源域名和用户存储位置不变。

更新启动清单后，版本工具校验所有实际运行文件的缓存号，不再硬编码只有9个参数；仍必须逐项比对清单，不能改成“数量随便”来让检查通过。ZIP/APK继续逐文件核对，排除测试、私有档案、凭据和真实存档。

## 11. 测试如何一起迁移

1. 统一测试启动器，直接加载与游戏相同的模块清单，注入内存存储、随机源、现实时间和宿主能力；测试按文件名定位错误，不再靠source.replace临时把私有函数塞进导出对象。
2. 旧正则断言逐条分类：玩法行为改为真实输入/输出与状态守恒；资源和安全接线仍保留结构检查；排版格式类断言只在有替代证据后退役。
3. 对高风险路径做旧/新双实现对照：相同输入、随机序列、时间与存储失败点，比较生命、物资、耐久、成长、费用、产出及结局。允许忽略的只有明确列出的诊断字段和现实时间戳。
4. 固定回归矩阵：当前普通/困难/传奇/噩梦，早期旧档与新档，主档/槽位/导入/复活，满包/仓满/零耐久/腐坏，中文/英文，手机/桌面/安卓生命周期。
5. 界面测试使用稳定的data-testid或语义角色，不依赖中文文案寻找业务入口；实际用户文案与翻译正确性另外验证。错误日志、截屏与失败退出码全部保留。
6. 不把断言过时直接判为可删除：写清原来防什么问题，先建立覆盖同一风险的新测试。已知产品缺陷另列修复提交，和等价重构分开。

## 12. 完成标准

- game.js与ui.js不再承担集中业务；即使保留同名文件，也只做兼容转发或启动，不能留下数千行原实现。
- 新增普通物品或武器，主要改内容定义、配方和文案；已有规则无需穿插补丁。新增特殊机制仍需明确规则模块与测试。
- 新增面板只登记一处路由元数据及功能视图，不同步修改几份弹窗名单。重复打开界面不重复执行、不漏释放暂停。
- 一次物资操作、一种伤害计算、一项资格检查均有唯一规则来源；预览与执行共同使用。
- 状态修改入口、保存失败回滚、读档迁移及旧接口归属能从文档与代码直接查到。
- 中文/英文和现有视觉/配音内容保留；热点坐标、存档、工具操作与安卓生命周期验收通过。
- 相同机器/场景下比较冷启动、背包100项、仓库连存50次、多敌战斗、反复开关100次面板和内存/监听数量；目标不劣于基线，超出约定波动须解释，不能靠主观“更快”验收。
- 源码可运行、测试可重跑、发布包文件校验有效；仅新增很多文件或减少行数不算完成。
