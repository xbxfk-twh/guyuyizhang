# 代码结构与安卓构建

整理日期：2026-10-10。保留纯JS入口、Game/UI/AudioFX公开接口及存档字段，逐功能整理，避免全面改写时再次引入旧档与状态错误。

## 职责边界

| 位置 | 职责 | 修改原则 |
|---|---|---|
| js/data.js | 物品、角色、场景、敌人、配方数据 | 数值与数据ID放这里，旧ID不可随意改名 |
| js/game.js | 状态、数量、时间、规则、事务保存 | UI只调用公开操作，不自行扣物品或改装备 |
| js/ui.js | 渲染、弹窗、触摸和战斗表现 | 数量、容量和可用性取Game接口 |
| js/audio.js | 音频层与开关 | 宿主暂停和玩家音量设置分离 |
| js/ads.js | TapTap H5激励视频 | 不支持时返回不可用，不伪造观看成功 |
| js/battle-effects.js | 战斗视觉效果 | 效果结束不能重复结算玩法 |
| css/style.css、panels.css、ui-polish.css | 基础场景、共用面板与视觉细节 | 面板布局集中处理，避免散落补丁 |
| 安卓包装/ | 原生外壳与可重复APK构建 | 只同步唯一游戏源码，不另写玩法 |

## 本轮整理的库存区域

game.js库存区域按保鲜→访问与容量→数量统计→装备实例保护→搬运预检→共同事务→仓库搬运→地窖→丢弃→自动规则排列，展开原来的长行。

- `storedCounts`：按记录合并数量，不丢批次信息。
- `storedSlots`：仓库格数统计，复用弹药50、普通20与装备逐件规则。
- `settleStoredFood`：岛仓、海仓、地窖到期转换，读档幂等。
- `commitInventoryTransfer`：统一在副本搬运；异常回滚内存，写盘成功才提交；恢复原事务标志。transferWarehouse、transferCellar、discardItems共用。
- 原有公开API全部保留，装备实例索引、数量、耐久、过期时间及localStorage存档语义不变。

## 存档读取边界（2026-10-17整理）

发行版号目前不在存档中，`v:1`不能解释成发行版1.00或用来判定1.10/1.12边界。历史数据转换集中保留，不在正常玩法中另加多套旧版分支。

`normalizeState`按顺序调用：补当前字段缺省值`fillStateDefaults` → 原有字段标记识别的`migrateLegacyState` → 死亡/继续状态`normalizeLoadedSession` → 耐久/工具实例对齐 → 账号投入物品对账 → 旧待收一次转换`migratePendingLoot` → 仓库存物保鲜结算 → 有版本标记的`applyBalanceMigrations`。主档、备份槽、导入和日出复活共用该入口。

新增历史转换应放在读取边界，注明识别字段与重复执行行为；当前安全校验仍放在真实操作所需的位置。不要按注释中的“旧版”字样删代码，也不要凭发行版号猜测存档格式。新增平衡补偿使用迁移标记，新局初始化到当前版本。公共待收接口只作无副作用兼容返回，旧物资转换在读入时完成，日常收入直接进背包并允许超载。

## 平台接口

原生壳仅调用 `UI.setHostSuspended(boolean)` 和 `UI.handleBack()`，不依赖弹窗DOM或直接操纵S。Game的宿主暂停是临时状态，与面板setTimeFreeze独立；AudioFX的宿主暂停不修改玩家音乐/音效开关。

APK构建、签名位置及功能限制见 [安卓工程说明](../../安卓包装/README.md)。BUILD_VER仍只由游戏index.html定义。正式发行签名、安卓广告SDK与服务端跨域接入需要分别完成，测试签名APK不能直接宣称这些平台能力已经适配。

## 后续整理原则

先为一个具体功能建立行为测试，再提取共享纯函数或事务边界；保持Game公开面与旧存档语义。战斗、存档、制造、场景各自仍在原文件内，不宣称已全部拆为独立模块。需拆文件时一并更新浏览器脚本顺序、缓存校验、测试载入器和导出清单。每轮完成核心回归、相关浏览器和旧档验证再继续下一域。
