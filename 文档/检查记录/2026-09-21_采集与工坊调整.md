# 采集与工坊调整（2026-09-21）

本清单**先于改动**记录：现状值 / 建议值 / 最终实际值。只改 3 个授权源码文件
（`孤屿遗章-游戏 - 发布/js/{ui,game,data}.js`）与 `css/style.css`；`css/panels.css` 本轮未改。
不改存档字段语义，只加字段。

## 1 装备工具栏待装备工具图标

- 现状：`ui.js` 工具栏候选区用 `<span class="inv-glyph">${ITEMS[id].glyph}</span>` 字形占位；
  已装备槽位（`data-toolslot`）用 `itemIcon(tid)`。
- 建议：待装备区同样走 `itemIcon(id)`，与背包/槽位一致；无 PNG 时 `itemIcon` 自身会 `onerror` 隐藏。
- 实际：候选按钮改为 `${itemIcon(id)}`。字形占位类保留给 `SPR` 未覆盖的物品。

## 2 采石 / 野莓 / 取水动画与 SVG

- 现状：`ui.js` `renderScene` 里按 `p.id` 正则决定 `imgHint`：
  - `/(stone|ore|quarry|crystal|pit|iron|niter|sulfur|fossil|clay|copper)/` → `hammer_icon`（锤子）
  - 其它 gather → 默认 `imgHint='gather'`（图片 `anim/gather.png`）
  - 野莓 `forest_berry` 命中不到石类正则 → 落到默认 `gather`，**不是**手摘浆果
  - 取水 `river_water` → 也是默认 `gather`，**不是**舀水
- 问题：石堆用"锤子"图（与石镐语义不符）；野莓/取水共用一张通用图，语义不准。
- 建议：给三类各做独立黑白 SVG 内联图案，经 `imgHint` 选到：采石→石镐、手摘浆果→手摘、取水→舀水。
- 实际：新增三个自绘黑白 SVG data-URI，在 `showBusy` 里 `imgHint` 命中即用作 `<img src>`；
  判定顺序为：树/竹→`axe_icon`；石/矿→`pick`（石镐）；`berry`→`berry_pick`；`water`→`water_ladle`。
  **不再误用锤子**（石类改为石镐），草药(`herb`)仍走默认 gather，不被石类正则误伤。

### 2b 采集结果日志时间

- 现状：`doPoint` 的 `gather` 分支 `pointCharge()` 后先 `addMin(...)`（`timePaidEarly`），
  再结算产出并 `log('获得：…')`；`log()` 记录的是 `S.minute`（结算那一刻的当前时间）。
- 期望：8:20 开工、耗 20 分，则"获得"应记在 8:40。
- 实际：确认 `addMin` 在产出日志之前执行，跨日由 `addMin` 内部 `while (S.minute >= 1440)` 处理，
  产出日志因此天然落在结束时刻。遇袭分支 `S._onFightWin = doHarvest` 战斗后回到结算，
  日志仍记录真实结算时刻（结束时间语义）。
  失败（背包装不下 / 未产出）不写"获得"，走"一无所获 / 背包满了"分支，不产出。
  死后产出：`pointCharge` 与产出都在死亡拦截前的 `hp>0` 假设下结算，`change()` 有 hp≤0 立即 `die()` 兜底；
  本轮不新增任何"死后给产出"的路径。

## 3 雨线方向与位移动画

- 现状：`css/style.css` 雨丝 SVG 每条线从 `(x, y)` 到 `(x-5, y+13)`——**向右下→左下**，斜率约 21°。
  动画 `@keyframes rainfall { to { background-position: -16px 470px, -28px 760px } }`，
  x/y 位移斜率约 1.9°，**与画出来的 21° 斜线不一致**（看着像直线下坠）。
  `rainfallslow` 同理（34px / 960px）。`.storm` 复用同一套 SVG 与 keyframes，
  场景层与地图层 `#weather-overlay` 共用这两组 class 与 keyframes。
- 建议：位移量与斜线角度一致 → 470px 竖直对应水平约 `470*tan(21°)≈180px`；760px→约 292px；960px→约 368px。
- 实际：`rainfall` → `-180px 470px, -292px 760px`；`rainfallslow` → `-368px 960px`。方向与斜线一致（左下）。
  **雪（snowmove/snowsway）未改**。

## 4 当前目标顺序 / 床恢复

- 现状 `currentObjective()`（day>1 后）顺序：1) 无床 →"铺一张草床"（**床最优先**）；2) 无工作台 →"造工作台"；3) 瞭望台…
- 建议：优先工具（石斧/石镐）与食水/工具台，再床。
- 实际顺序（2026-09-21 定稿）：day1 提示不变 → **食水危急（hunger 或 thirst <30）** →
  **至少一把斧/镐** → **造工作台（解锁制作）** → 再铺草床 → 瞭望台…
- ⚠️ **食水与斧镐提示不看床**：即使已有床，只要饥渴 <30 或缺斧镐，照常提醒——
  床只排在满足「吃喝+工具有」之后、「瞭望台」之前。
- 已核实新手引导（`tut`）路径：`tut=1` 提示做石镐、`tut=2` 提示上工具栏，均不依赖床、不依赖工具台，
  与 day1 目标（生篝火搭帐篷）不冲突。

### 床恢复数值（现状 → 建议 → 实际）

`ui.js sleepRec()` 体力：`sta = round(min(maxStam, maxStam * (0.45 + houseRest*0.12 + bedRest*0.32) * sq))`

| 设施 | rest 现状 | 现状体力系数(sq=1) | 建议 | 实际值 |
| --- | --- | --- | --- | --- |
| 无床（bedRest=0.4 兜底） | 0.4 | 0.45+0.12hr+0.128 | 保留 | 0.4（不变） |
| bed1 草床 | 0.7 | 0.45+0.12hr+0.224 | 约 -20% | 0.58 |
| bed2 木床 | 0.9 | 0.45+0.12hr+0.288 | 恢复原值 | 0.9（不变） |
| bed3 软床 | 1.0 | 0.45+0.12hr+0.32  | 恢复原值 | 1.0（不变） |
| bed4 大床 | 1.2 | 0.45+0.12hr+0.384 | 不削弱高阶 | 1.2（不变） |

只下调初期草床 bed1 `rest`，保留"无床<草床<木床<软床<大床"清晰递增；木床/软床/大床维持原值。
`spirit`（精神）与 `sleepH`（统一 8 小时）不变。

**rest 是否影响血量/精神？** 已核对：`rest` 仅通过 `bedRest*0.32` 进入体力恢复系数
（`game.js sleep()` 的 `staGain` 与 `ui.js sleepRec()` 的 `sta`），血量恢复走 `hungPen/thirsPen/spiritPen`
（与 rest 无关），精神恢复走 `bf.spirit`（与 rest 无关）。**故 rest 本身已经只作用体力**，
无需再新增 `staminaRest` 字段——不会有"误削血量/精神"的风险。

## 5 野兔 / 怪物伏击概率

- 现状 `doPoint` gather 分支：`danger = sceneOf(S.scene).danger`；
  - `danger <= 2`：`amb=0.05, rabbit=0.10`
  - `danger >= 4`：`amb=0.20`（无野兔）
  - 其余（danger 3）：`amb=0.10, rabbit=0`
  另有点位专属 `p.risk` 25%、海底哨兵 12%。
- 用户以为"前期每次采集野兔 10%、怪物 5%"：只在 **danger ≤ 2 的前期安全区**成立。
- 建议：如实写清；**保持原概率不改**。
- 实际：仅本文档写明条件，代码概率一字未动。

### 家具

- 沿用旧 ID 语义：`wb1/wb2/wb3`（`station` 仍 `work1/2/3`）显示名改为
  「简易工具台 / 精工工具台 / 高级工具坊」，负责工具武器原配方。
- 新增家具 `tailor`（裁缝台），`station='tailor'`，负责麻衣与适合的衣物配方；
  纺车/织布机（`spin`/`loom`）不动。
- 裁缝台成本：`{ wood:6, branch:4, vine:1 }`（不依赖自身产物，不卡 fiber/cloth）。
- 旧档兼容：读档时若已有 `wb1/wb2/wb3` 任意一级 → 补**顶层** `S.tailorGift=1`（一次性落定，
  不写 `S.furniture.tailor`），此后 `tailorGifted()` 判真即代表裁缝台可用。赠送**不占家具位**、
  不可拆除、也不可重复建造（`buildFurniture` 有"已经可以用了（随旧工作台一并补发）"分支）。
  新局 `S.tailorGift=0`，需独立建造裁缝台。
- ⚠️ **家具位占用（2026-09-21 修复）**：`furnitureUsed()` 中 `tailor` 不再与 `wb1..3` 合并成一槽——
  新造的 `S.furniture.tailor` 单独计 1 个 `single` 槽（gift 不在 furniture 里故天然 0 槽）；
  `furnSlotFull('tailor')` 去掉"只要有任意工具台就白给免费槽"的旧逻辑，仅保留
  `S.tailorGift===1` 时不占槽（此时走"已赠"分支，本来也不会真建）。
