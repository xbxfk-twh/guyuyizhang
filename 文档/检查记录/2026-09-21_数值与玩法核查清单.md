# 数值与玩法核查清单（2026-09-21）

作者这轮转述的反馈逐条核实。**结论：真 / 假 / 部分真**。标「待拍板」的只列数字和我的建议，没有动代码。

---

## 一、确认是真问题

### 1. 遗迹守卫硬到玄铁装备也打不过 —— **真，而且数字能算出来**

守卫基础值：HP 120 / 攻 20 / 防 8 / 速 6，带 `ironImmune`。

难度乘数 `enemyMul` 只乘 **HP 和攻击**，不乘防御：

| 难度 | HP | 攻击 |
|---|---|---|
| 求生者 | 72 | 12 |
| 冒险家 | 102 | 17 |
| 幸存者 | 156 | 26 |
| 传奇 | 192 | 32 |

第三档（幸存者）拿玄铁剑+玄铁甲去算：

- 我方攻击 = 5（基础）+ 18（玄铁剑）≈ 23 → 单次伤害 23 − 8 = **15**
- 击杀需要 156 ÷ 15 ≈ **11 次出手**
- 敌方命中一次：26 − 8×0.8（防御效率 80%）= **19.6 ≈ 20**
- 玩家血量约 111 → 挨 **6 次**就没了

速度和出手次数救不回来。所以"打不过"不是幻觉，是**攻击被难度乘了、防御没跟着乘**造成的单边膨胀。难度越高，这个缺口越大。

**建议（待拍板，三选一）**

- A：`enemyMul` 改成只乘 HP，不乘攻击 —— 一刀切，影响所有怪物，简单但会整体变软
- B：给玩家防御也吃一个难度补正（例如幸存者 +15%、传奇 +30% 防御）—— 只影响挨打侧
- C：只调精英/BOSS 的攻击成长，普通小怪不动 —— 最保守

我倾向 **C**，因为它只动出问题的那一类，不会把新手体验连带改掉。

### 2. 消耗魂点回日出，有时候怎么点也回不了 —— **真，是界面反馈坏了**

逻辑本身是对的，坏在按钮：当"魂点够 50，但当天日出记录无效"时，代码会把整段理由塞进一个**禁用按钮**里显示。那段理由有四十多个字，在手机上根本看不全，看起来就是个点不动的坏按钮。

已修：按钮改成短的「回到今天日出（不可用）」，完整原因单独一行显示在按钮上方。

顺带说明真实原因通常是：**旧存档**在第一次日出之前没有日出记录，过了那个日出就自动有了。这不是 bug，是读档后的正常空窗。

### 3. 提示不明显，很多人不知道劈柴能出树枝 —— **真**

`劈柴` 是制作页「手工」里的配方（木柴×2 → 树枝×4），是树枝的**唯一**来源。但制作页没有任何地方提示这件事，玩家缺树枝时只会看到"材料不足"。

**建议**：缺树枝的提示里补一句「树枝可用木柴「劈柴」得到」，并在邮箱攻略页加一条。这条改动小、收益直接，等你点头就做。

### 4. 每日签到和公告写的不一样 —— **真，已修**

v1.07 公告写的是「魂点 ×30 + 备份点 ×2」，实际给的是 10 + 1。已把那行改成：

> 每天可领 魂点 ×10 + 备份点 ×1（早期版本曾是 30 + 2，后续版本已下调，以此为准）。

## 二、查完发现是假警报

### 5. 困难难度没有历代遗章场外加成 —— **假，本来就有**

`metaAllowed()` 放行的是 求生者 / 冒险家 / 幸存者 / 开发者，**只排除传奇**。幸存者（第三档）一直享受传承加成，描述文字里也写着。这条不用改。

### 6. 嗜血狂刀只能匕首用，进海前等于废技能 —— **已经解决了**

钢匕首（攻 11 / 速 14）和玄铁匕首（攻 14 / 速 14）都已经存在，配方分别是 钢锭×2+皮革×1 和 玄铁锭×2+秘银锭×1，技能描述也写明了双匕首触发。这条是上一轮就做掉的。

### 7. 长时间批量制造不出弹窗、反而什么都不做 —— **本地测试是通的**

探针实测：长批量会弹出确认窗，确认前不扣材料，点「仍然开工」后确实做出 40 块木板。文件名 `回归测试/_out/mobile-batch-warning.png`。

**但要注意**：这是 Chrome 手机模拟，不是真机 WebView。真机上如果长按没被识别成"长按"（被页面滚动手势吃掉），玩家就进不了批量窗，体感和"没反应"一样。这条我按**真机待验**挂着。

## 三、各难度命中率（现状，供你平衡参考）

**难度完全不影响命中率**，影响命中的只有这些东西：

| 情况 | 命中 |
|---|---|
| 近战（默认） | 90% |
| 近战 · 恐惧状态 | 70% |
| 近战 · 猎人身份 | +10% |
| 重击 | −20% |
| 横扫 | −15% |
| 投掷长矛 | −10% |
| 目标带「闪避」 | −20% |
| 弓 | 90% + 弓术每级 +5%（上限 95%） |
| 火枪 | 60%；校准后 70%；+ 枪械精通每级 +10%（上限 95%） |

**"十打九空"的来源找到了**：雪羽鹰带 `evade`（闪避），对它的命中直接掉到 **70%**；它速度 14、玩家拿玄铁剑速度只有 8，它出手还比你勤。70% 命中 + 被压制出手数，体感就是"我一直在打空、它一直在打我"。

**建议（待拍板）**：闪避的 −20% 有点重，考虑降到 −10%，或者只对"重击/横扫"这类大动作生效。你定。

## 四、战斗系统要不要重构

**结论：不用重构。**

现在的骨架是完整的：距离制（近战 0 / 弓 30 / 枪 15，速度决定每回合前进多少）、时间制冷却（横扫 CD 从 20 秒减到 1/10）、技能树（基础主干 + 两侧专项 + 互斥）、buff 生命周期（同属性覆盖、按 tick 到期）。

真正缺的不是机制，是**信息**：玩家看不到自己这回合为什么没打中、看不到 CD 还剩几秒、看不到距离还差多少。加可视化的收益远大于改机制。

所以我建议下一轮做「战斗信息面板」，不动战斗公式。

## 五、手机端

### 8. 家具那个问号点不开 —— **没复现，怀疑是真机点击问题**

代码路径是通的：问号按钮绑到 `showModal('camphelp', {mode:'furn'})`，家具说明是完整生成的；CSS 里触屏下按钮最小 44×44。逻辑上不该点不开。

最可能是**真机上营地弹窗在滚动，手指落在问号上被判定成"开始滑动"**，所以没触发点击。

**建议**：不用等方法复现，直接把问号按钮的触控区再放大、并加上"滑动超过阈值不算点击"的容错 —— 这类改动无风险。等你点头。

已经做了启动容错、资源压力优化和 Chrome 故障注入，但**没有真机**，所以不能声称解决 WKWebView / TapTap 宿主的问题。需要你那台机器复现一次并给我诊断信息。
