# 日出回溯与源质装备链（2026-09-22）

本轮先记录数值/配方变更清单，再改数据。分两个闭环：①日出回溯存档安全与材料返还；②源质长枪/重甲可获取链（总规划第零节 + 1.8，设计已定）。

## 一、日出回溯（规划 1.6）

### 现状核实

- 回溯调用路径：`ui.js showEnding()` 死亡后点「回到今天日出（-50 魂点）」→ `Game.reviveToday()`。
- `dawnCheckpoint` 生成：`game.js snapshot('day')` 在 `newDay()` 结尾（line 737）与 `newGame()`（line 1077）写入 `S.dawnCheckpoint = {version:1,state}`。
- 持久化：`save()` 里 `copy._snap = undefined`（不落盘临时快照），`dawnCheckpoint` 属于 S 的普通字段会随存档写盘。
- 恢复：`reviveInfo()` 校验 `dawnCheckpoint.state.day === S.day` 且 hp>0；`reviveToday()` 深拷贝快照为新 S，`next.dawnCheckpoint` 保留旧值，`meta.soul -= 50`，`persistPair` 落盘。

### 结论（未发现需要修复的 bug）

- 快照在 `newDay()`（材料尚未消耗）时拍摄，回溯回滚的是完整局内状态（含 inv / toolDurs / equipment / stats / minute），理论上材料、耐久、装备、时间均完整恢复。
- 魂点在 `meta`（账号级）单独扣除，`dawnCheckpoint` 只存局内状态、不含 meta，不会被快照反向返还。
- 本轮**保留原实现**，仅补行为级测试证明反馈真假并防复发。

### 补测试（回归测试/dawn-revive.test.js）

- 日出快照后记录木材/食物/耐久/装备/时间 → 当天消耗材料与耐久、推进时间 → 回溯 → 断言恢复。
- 覆盖：首次使用 / 连续尝试 / 旧档无 dawnCheckpoint / 跨日新快照；不清理真实 localStorage（用内存 store）。
