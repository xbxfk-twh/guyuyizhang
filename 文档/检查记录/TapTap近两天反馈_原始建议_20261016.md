## 4. 可直接执行的任务卡

### T01 制作失败原因可见

问题：玩家先看到材料或矿物，攒齐材料后仍无法制作高炉；回复中才指出还需图纸。前置条件不透明会让正常解锁规则看起来像bug。

建议：制作面板完整列出条件，并在禁用按钮旁显示最关键原因，例如“缺少：高炉图纸”。能够查到来源时给出已确认的获取途径；未探索区域可显示概括提示，避免强行剧透。显示用的条件检查与实际制作校验应共用规则，具体函数和文件由工作区按代码确定。

先查：当前高炉是否确实需要图纸；材料统计是否同时考虑允许使用的仓库；家具空间、工作台、数量等是否也可能拦截；已有提示是否被遮挡或过时。

验收：

- [ ] 材料足够、没有图纸：明确提示缺图纸，不能无反馈。
- [ ] 有图纸、材料不足：准确列出缺口；仓库/背包来源遵循实际设计。
- [ ] 多个条件同时缺失：能够查看完整列表。
- [ ] 所有条件满足：制作成功且只扣正确物资；界面显示与校验一致。
- [ ] 用新档和旧档各验证一次，不篡改旧档的解锁状态。

### T02 自动进食可控，避免误食饲料与稀有物资

建议：先加入每种物品“允许自动食用/禁止”与保留数量，再在允许范围内按玩家选择或临期顺序吃。临期优先只能在营养、安全等现有规则允许的食物中执行，不能为了防腐坏而吃有害物品。明确显示下一份将吃什么、从哪里取。不要把小麦、蜂蜜等一刀切禁止——它们也可能是玩家主动选择的食物。

排查：是否仅按物品列表顺序遍历；烤肉是否属于可自动食用类型；储存区域/地窖限制是否使其不可选；腐坏时间是否正确参与选择。以上都仅是假设。

验收：

- [ ] 复现组合：地窖有临期烤肉与小麦，小麦被设为保留；自动进食不扣小麦。
- [ ] 被禁止物品不会因批量制作、睡眠、赶路等时间推进被吃掉。
- [ ] 保留量、优先规则在保存和重新进入后仍有效。
- [ ] 没有合规食物时给出说明，不悄悄突破玩家限制。
- [ ] 检查背包、仓库与地窖的实际可用范围，避免跨区域错误取物、重复扣除和负数。

### T03 冬季取水可持续性核查

先按难度、角色和阶段列出：每份雪可换多少可饮用水、每天能获取几次、采集/融雪成本、每天基础与行动耗水、可储存容量。玩家称“两三个”没有说明单位，不能据此直接调整成固定倍数。

建议：若已有冬季水源，补足入口、解锁提示和用途说明；若日常消耗确实无法覆盖，再选择提高雪产出、融雪效率或添加一种合理水源。先完成一种可持续方案，避免同时大改多个系统。入冬前明确提示风险及准备途径。

验收：

- [ ] 对一个合理准备的前中期存档模拟连续7个冬日，记录水量和获取成本，确认有可行生存策略。
- [ ] 另测没有高级设备的玩家能否找到应急方案；确需预备资源时，提示在入冬前可见。
- [ ] 不因保存/重进重复领取当日产量；融雪和装水容量正确。
- [ ] 区分正常难度压力与实际资源死锁，不默认取消生存挑战。

### T04 食之包的规则和实际状态一致

建议：道具说明列清生效位置、所需设施、允许来源、触发条件；界面展示“已生效”或具体未生效原因。使用T02的禁食/保留规则保护稀有物资。S1能从地窖自动进食、S2对生效方式困惑，两者不一定处于相同进度或版本，不能直接判定互相矛盾。

验收：无地窖/有地窖、背包有食物/只有仓库有食物、岛上/海底区域分别验证；显示结果与实际取物一致；说明中的位置名称使用当前版本的正式名称。

### T05 减少吃喝和维护的重复操作

建议：优先尝试取水时可选“补充饮水”、明确的一次吃到目标值、以及在同一面板查看主要生存状态。长时间制作前预览时间、预计资源变化和风险。具体是否支持自动补充由游戏设计决定，不能在玩家不知情时额外消耗物资。

验收：完成相同一次外出准备，对比修改前后的点击/切页次数；不改变未获设计确认的时间消耗规则；批量操作正确扣除数量；危险状态仍及时可见。

### T06 材料负担与高级工具收益

建议：列出石/铁/钢阶段，每次采集的净木材、每单位体力与游戏时间收益、主要建筑升级总需求及转换损耗。优先让现有高级工具、批量加工或设施升级承担减负作用，再评估新增锯木/切石设备。玩家提出3→6→9木板是方案示例，不能直接当成定案，也不要未经核算新增家具占格压力。

验收：相邻工具等级在相同条件下有可感知的效率提升；主要建材升级所需行动数有记录；木材与铁矿的阶段性需求失衡得到解释或调整；旧物资与旧档可继续使用。

### T07 重武器首击与耐久成本

建议：先确认首次攻击是否要等待完整攻速周期、双方是否对称、受击耐久按什么计数。比较“首刀立即、后续按攻速”“主动技能起手”等方案，不直接给重武器免费先手。界面清楚显示行动进度，避免被误解为无响应。

验收：轻武器、双手大剑分别对低威胁小怪和强敌模拟首击时间、战斗时长、承伤与耐久损失；确认高攻击力没有因新起手规则获得失衡收益；防具和饰品按设计耐久规则扣除，不把所有掉耐久都当bug。

### T08 前置链和新手目标

建议：把“制作界面的船坞”和“地图地点船坞”区分清楚；围绕下一项可达目标展示必要前置条件。检查第1次交换任务是否仍有价值。高级资源可预览，但应显示当前用途与解锁限制，避免让玩家误以为已能使用。保留自由探索，是否隐藏龙骨等内容由设计决定。

验收：新玩家不查外部攻略，能够从面板回答高炉为何不能做、下一步去哪解锁；任务不引用已经失效的配方或位置名称；已提前解锁的任务能正常结算或跳过。

### T09 天赋回报

建议：升级前展示下一等级的实际差异，并记录首点天赋的获取周期、常见行为的收益变化。先审查弱节点和说明，再决定数值调整，不能只因一位玩家抱怨而全树加倍。

验收：关键天赋能用明确数值或效果解释收益；至少对采集、生存、战斗三个方向做代表性对比；未升级、升级后和重进存档的效果一致。

### T10 剧情和文本精修

建议：选择开场、老潮初次交易、一个阶段目标和一个关键结局作为小范围精修。统一角色语气、材料/设施术语、玩家当前目标；语音与文字一致。先形成一段连贯体验，再扩写内容。

验收：这些节点说明玩家为什么行动、发生了什么变化以及下一步目标；与实际解锁条件和现有配方一致；删改不破坏已触发的任务或结局标记。

## 6. 推荐实施顺序

1. **先核查版本和条件**：记录当前构建，确认T01、T02是否已修；复制测试存档进行验证，不对玩家原档直接试错。
2. **第一批交付**：T01失败原因提示、T02自动进食保护、T04生效状态说明。T03先产出取水收支核算，再提交最小必要改动。
3. **第二批交付**：T05减少重复操作、T08引导衔接；结合数据实施T06材料效率、T07重武器节奏、T09天赋回报。
4. **随后内容打磨**：T10与图鉴检索。避免把大量新系统和紧急缺陷修复塞在同一个版本里。

没有证据支持直接大改所有难度、删除健康/精神系统、照搬玩家建议的攻击百分比或新增大批建筑。本报告不规定代码文件名、精确数值或工期，因为尚未读取项目。

## 7. 给开发工作区的执行指令（可直接复制）

> 请阅读本报告并先检查《孤屿遗章》当前项目、版本和已有修复。逐项给出“已修复 / 可复现 / 仅文案问题 / 设计评估 / 信息不足”的状态及依据。优先实现T01、T02、T04；T03先核算当前冬季水循环再决定改动。不要把报告中的排查假设当作已确认根因，不要照搬玩家示例数值。保留游戏的生存压力和旧档兼容性，完成每项对应的验收清单。最终列出改动文件、行为变化、验证结果及仍未解决的问题。当前任务是依据反馈修改游戏，报告本身并不证明任何修复已经完成。

## 8. 覆盖限制

本报告来自已登录网页的可见评价、论坛主帖与所核查的回复，不包含私信、QQ群反馈、已删除内容或所有历史帖的新增回复。未向任何玩家发送消息，未发布回复，未改动游戏代码。S3认可服务态度，S1认可挑战，S2也认可核心玩法的吸引力；应在修复卡点和重复劳动的同时保留这些优点。
