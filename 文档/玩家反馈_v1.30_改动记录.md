## 1. "存档退个后台再回来，莫名其妙就消失了"

**机制**（不是玄学，是手机浏览器的老毛病）：

1. 手游玩家的进度只存在浏览器 localStorage 里，**写盘是"之后才落"的**——玩家一做动作，游戏并没有立刻把整份存档写进去；
2. 手机切后台 / 微信里切出去 / 系统低内存回收，页面可能在"还没写"的时候就被杀掉 → 这次进度整段没了；
3. 还有一种更隐蔽的：**同一台设备开了两个标签页**（或收藏夹又打开一次），后开的那页拿着**旧的**进度继续玩，一存档就把新的盖掉了。

**现在加的防线**（7 层，全部有回归断言）：

| # | 防线 | 作用 |
|---|---|---|
| ① | 写完**读回来校验** | 配额满/被浏览器限制时不会"当成存好了" |
| ② | 存档版本号 `guyuyizhang_rev` | 另一个标签页有更新进度时**拒绝覆盖**，弹窗让玩家选 |
| ③ | 存不进去**立刻弹窗** | 直说"去导出存档码"，不再无声丢档 |
| ④ | 每 20 秒兜底自动存档 | 只在状态真的变过（`_dirty`）时写 |
| ⑤ | `pagehide` / `beforeunload` / **`visibilitychange`** | 切后台、关页面、锁屏那一刻立刻写一次 |
| ⑥ | `pageshow` 回前台重新同步 | 从后台回来先对齐盘里的版本号，避免拿旧进度覆盖 |
| ⑦ | 备份面板显示"上次保存时间" | 玩家自己就能看出存档有没有在动 |

**给玩家的话**：定期在「菜单 → 备份·读档」导出一次存档码（复制到备忘录/微信都行），
换机换网址都能贴回来。另外**别同时开两个标签页玩**。

## 2. "战斗时血量有时候会卡住：怪实际扣血了但血条不掉"

**先证明了不是换算错**：写了无头浏览器探针 `开发工具\检查\_debug_fightbar.js`，
在真实浏览器里跑真实战斗，逐回合比对「引擎 `C.enemies[].ehp`」和「DOM 血条宽度」，
7 种敌人（含群袭 / 会召唤的 Boss）共 **1800 多次出手，0 次不一致**。

**真正的原因有两个，都修了**：

1. **渲染方式在移动端 Safari 上会漏重绘**：`#fight-targets` 是 `position:sticky` 的独立合成层，
   而代码**每一回合都把它的子树整个 `innerHTML` 重建**——iPad/iPhone 上有时候不重绘，
   玩家看到的就是"数字在动、血条不动"。
   → 改成**原地更新**：血条元素建好就不再重建，只改宽度/数字/意图标签。
   顺带 CSS 的 `width` 过渡终于能跑起来，**血条会平滑地掉下去**，玩家看得见。
2. **横屏手机上血条被顶出屏幕**：战斗弹窗里那张 250px 的怪物立绘 + 解说，
   在 390px 高的横屏手机上把「敌人血条」整个挤到屏幕外（实测 `scrollHeight 386 > clientHeight 337`）。
   玩家打怪时根本看不到血条，只能自己往下滚。
   → 加了矮屏样式（`@media (max-height: 620px)`）：立绘压到 18vh、日志压到 46px、
   标题/间距收紧。现在一屏放得下「怪物图 + 你的血条 + 敌人血条 + 日志 + 按钮」（实测 316=316，不溢出）。
   → 另外，点攻击要选目标时，血条列表会**自动滚进视野**。

**顺手修掉的两个真 bug**：

- 选目标的**黄框**和"已选定"的**白框以前根本没生效**：CSS 把 id 当 class 写（`.fight-targets`），
  整段选择器是死的。现在全部改成 `#fight-targets`（首领名字配色、血量数字配色也一并修好，
  数字颜色从看不清的 `#8a8571` 提亮到 `#c9c2ab`）。
- **上一场残留的"待选目标"** 会带进下一场（开局就带黄框、点血条会误触发一次攻击）；
  另外"战斗结束 1 秒后关窗"的定时器会把**这 1 秒内新开的战斗**一起清掉（连续遇袭/多波夜袭时）。
  两条都加了防护。

## 3. "草床是不是没什么用啊，空占一个位置"

**查明的根因**：床的数据里 `rest`（舒适度）和 `sleepH`（睡眠时长）**两个字段从来没被用过**，
睡觉只吃房子的 `houseRest` 和床的 `spirit`——所以草床确实只是"占一个家具槽"。

**现在**（引擎与睡眠面板用同一套系数，回归里逐条断言）：

- 体力恢复 = `上限 × (0.45 + 房屋舒适 ×0.12 + 床舒适 ×0.32) × 睡眠质量`；
- **没床 = 睡 9 小时**（翻来覆去，恢复最差）；床越好睡得越短：草床 8h / 木床 7h / 软床 6h / 大床 5h，
  睡越短扣的饱食和水分越少。

| 环境 | 一晚能补的体力 |
|---|---|
| 帐篷 · 没床 | 65% |
| 帐篷 · 草床 | 75% |
| 木屋 · 木床 | 86% |
| 砖瓦房 · 大床 | 98% |

另外精神恢复：没床 +5、草床 +6、木床 +7、软床 +9、大床 +10。

# 作者 2026-09-15 的三条定调

## A. 进地图要自动居中，但绝不越界（推翻 v1.06 的"完全不做自动居中"）

- **做法**：进地图（从场景回地图、旅行落地）时，把「你在这里」那个锚点对到画面中央；
  算出来的平移量会**夹在"整张图仍然盖满舞台"的范围里**——地图不够大时就居中到能居中的极限，
  绝不允许拖出黑边。只在"刚进地图"居中一次，之后玩家自己拖，重渲染不会把视角抢回去。
- **实测**（`开发工具\检查\_debug_mapcenter.js`，12 个场景 × 桌面 / 横屏手机 / 超宽屏 3 种尺寸）：
  锚点全部在画面内（原来是"从营地出来看不到营地"），没有一次露出黑边；
  拖动后连续重渲染两次，视角纹丝不动。
- **注意**：因为"不许越界"，像营地(y=88%)、山顶(y=14%) 这种贴近上下边缘的地点，
  只能居中到"图的边界顶住舞台"为止（桌面 1280×740 时营地大约停在屏幕 86% 高度处）。
  想让它真正居中就得把地图放大到 4 倍以上——那会破坏"一眼看到整座岛"，所以没做。
  如果作者觉得不够居中，可以调 `mapZoom()` 的下界（现在 1.15）整体放大一点。

## B. 热点保持"死位置"

维持现状：热点坐标钉死在地图百分比上，只随地图一起移动，被画面裁掉就跟着滑出去、拖回来自然重现。
**不再尝试任何"浮动标签 / 贴边堆叠"**（作者明确说：乱改怕再出问题，死位置玩家起码能点到、也不会乱）。

## C. 鸡舍 / 羊圈的"地图立绘"暂时不画

先保留在待办里；现在建了鸡舍羊圈，地图上不单独画一栋小房子。

## 1. 「不满足条件点进不去，体力却照扣」（蛛巢/蜘蛛女王）

**根因**：`doPoint()` 是"先扣体力+占当日次数，再分发到各个分支"。而狩猎类分支里还可能
早退——"现在这里没有猎物"、或者首领要先弹「确定讨伐？」——玩家一撤退，钱已经扣完了，
当日次数也被占掉，再点只会显示"今天这里已经来过了"。

**修复**：把所有"扣费"收进 `pointCharge()`，并在扣之前做一次**预检**：
狩猎先把猎物抽出来（抽不到就明说"没有猎物"，不扣）、首领先弹确认框，点「迎战」才
`pointCharge()` + 开打；海底闸门（远方的海沟）也改成先检查船/装备再扣。

## 2. 「手机下面菜单栏好难点」→ 底栏 20px → 30px

`@media` 里的 `--navh` 从 20px 改成 30px（和桌面一致）。日志贴底的基准也吃这个变量，会自动跟着走。

## 3. 「战斗武器好像不掉耐久」（石矛主手 + 石匕副手，只有匕掉）

**这是本轮最严重的一个 bug，而且顺带解释了上次那条"血条卡住"**：

```js
const usedW = ... ? meleeWeaponNow() : null;      // 返回的是【物品对象】
const wTag = usedW ? `〔${wNameOf(usedW.id)}〕` : '';
```

物品数据里绝大多数条目（石矛/石匕/铁剑…）**没有 `id` 字段**，所以 `usedW.id` 是 `undefined`，
`wNameOf(undefined)` 直接抛异常。而这一行正好夹在
**「伤害已经结算(tg.ehp 已扣)」和「刷新界面 / 扣武器耐久 / 判定战斗结束」之间**：

- 双持两把近战武器时，每次命中都炸 →
- ① 怪掉血了但血条和战斗日志都不动（`updateCombat` 根本没被调到）
- ② 武器耐久永远不掉（`drainWeapon()` 在抛异常那行后面，压根没执行）
- ③ 战斗还可能卡住（`endFight` 也走不到）

**修复**：改成取"这一挥用的是哪个装备槽"的 id（`S.equipment[weaponTurnSlot()]`），
并给 `wNameOf()` 加了兜底。实测双持 8 次挥砍：石矛 12→8、石匕 18→14，两把轮流掉。

## 4. 「背景音乐像湿塑料拖鞋蹭地板」

**原因**：配乐是**每个音都从音阶里重新随机抽**——只有乱跳没有旋律，还会随机翻八度，
随机撞到邻近音就成了刺耳的摩擦声；混响又用了 0.42s/35% 反馈的"梳状滤波"，听着发闷发塑。

**改动**：旋律改成五声音阶上的**级进**（一次最多走两格、绝大多数走相邻音），
起音放慢到 0.45 秒、加一层低八度轻和声；混响改成 0.30s/22% 反馈的更短尾巴；
夜里虫鸣从 4 声 4.3kHz 方波改成 2 声柔和正弦。**这条要你自己听一耳朵**，
不行我再调（音阶、密度、音量都在 `js/audio.js` 的 `startMusic()`）。

## 5. 「新手引导点跳过，并没有跳过」

**根因**：跳过按钮里写的是 `change()` ——但 `ui.js` 的作用域里根本没有这个函数（它是 game.js 内部的），
一点就 `ReferenceError`。同一个坑还害了另外两处：**领邮件后邮箱不刷新**、**兑换码不跳到邮箱页**。
三处统一改成公开 API `Game.change()`。现在实测：点跳过 → 引导条立刻消失。

## 6. 「石斧耐久没了还挂在装备栏」

**根因**：工具用坏被移出背包后，`S.toolkit` 里还留着那个 id —— 工具栏就显示一个 0 耐久的空壳。

**修复**：新增 `syncToolkit()`（每次 `change()` 和用坏工具时都会跑）：把已经不在背包里的工具从栏里清掉，
清掉之后再把背包里的同款工具自动顶上（就是玩家期望的"用完自动接着装"）。
另外**工具栏格子和背包工具列表现在直接写耐久数字**（"耐久 9/25"，用坏了红字标"已用坏"），
不用再点开看。

## 7. 「我怎么救了四个小满？一次性点位很多都有 bug」

**根因**：`adventure` 类的一次性点位不会自动打标记（`doPoint` 只给非 adventure 打），
必须由分支自己在"奖励到手"时调 `markDone()`。这次把 12 个一次性点位全过了一遍，
抓到 2 个漏的：

- `sea_rescue`（救小满）——救成功没打标记 → **能救四次**（玩家遇到的）
- `desert_remains`（荒漠白骨旁的破包裹）——搜完没打标记 → **能无限刷金币**

两个都补上了 `markDone()`；另外给 `pointAvailable` 加了"小满已经在营地就直接关闭"的兜底，
老存档（已经救过好几次的）也能收口。现在 `开发工具\检查\_check_once_points.js` 全绿，
以后新增一次性点位可以直接跑它体检。

# 大地图尺寸规则 · 最终版（作者 2026-09-15 第二次定调）

**规则**：大地图 **宽度 = 屏幕宽度**（手机 / 平板 / 电脑同一套），高度按原图比例算出来，
多出来的部分**上下拖动**看；**横向锁死**。

**为什么之前"没显示完全"**：老实现用的是 `cover`（等比放大到"盖住整屏"）。
为了让高度也铺满，图片被放得比屏幕宽 —— 于是左右两边被裁掉，玩家看到的正是"地图没显示完全"。
改成宽度贴合后，整张图的左右都能看到，只有高度需要滑。

代码上：`mapBox()`（宽度贴合）取代了 `mapZoom()+coverBox()`（地图专用），
`mapPanX` 恒为 0，纵向仍按 `maxPan` 夹在边界内（拖不出空白）；进图自动居中也只做纵向。
`coverBox()` 保留给**场景**用（场景仍然是铺满）。

**实测**（`_debug_mapcenter.js` 12 个场景 × 3 种尺寸 + `_debug_atlmap.js` 两张图）：
全部"宽度贴合 ✓"、当前所在地都在画面内；手机上海底图 842×561（屏幕 844×330）→ 有 231px 可上下拖。

**一个几何上的必然**：孤岛图是 1280×720（1.78）。如果屏幕比例比它更"高"（比如电脑 1280×740 = 1.73、
iPad 1024×708 = 1.45），宽度贴合后高度就不够填满屏幕，上下会留一条底色。
电脑上只有 11px（几乎看不出），iPad 上约 66px。
**要么这样（宽度优先、可能留一点上下底色），要么改成"至少铺满高度"（会把左右各裁掉一点点）**——
作者说一句就行，一行代码的事。

# 热点被日志栏盖住（作者 2026-09-15）

体检脚本 `开发工具\检查\_debug_hotspots.js`：**每个场景 × 每个热点 × 4 种屏幕**
（1280×800 / 2340×1080 / 844×390 / 1024×768），量热点矩形和日志栏矩形的实际重叠。

## 查出来的事实

- 日志栏宽度固定 **250px**（设置里可切 190/250/330），左缘贴屏幕左边，
  所以**画面左侧那条固定被它占着**：手机上相当于吃掉 30% 的宽度、iPad 上 24%。
- 日志栏 `z-index: 9`，而场景热点 `.hotspot` 是 `z-index: 6`、地图箭头也是 6
  → 落在那条上的热点**真的被压在底下**（半透明挡着、还挡住了点击）。全场景共 30+ 个热点受影响。

## 两手一起做

1. **把热点抬到日志栏之上**（`#hotspots` / `.hotspot` / `.map-arrow` → z-index 10，
   日志栏仍是 9；日志收起按钮提到 12 保证它还能按）。热点自带深色标签底板，
   压着日志也读得清。实测：**没有一个热点点不到**（探针用 elementFromPoint 逐个验证）。
2. **把压得最狠的 12 个热点往右挪 2~6 个百分点**（保持贴着自己的景物，别挪到别处去）：
   荒漠遗骸、河畔黏土滩/漂流物、树林砍伐、竹林砍竹、采石场黏土堆、草地狼穴、
   山顶雪线兽迹/石碑残迹、沉船湾宝箱、海域求救信、废墟三个（遗迹石板/深入废墟/石门守卫）、
   礁石栖息地"查看大地图"，以及海底海沟/沉船/珊瑚森林/深水圣殿的四个。

## 为什么不能只靠"挪"

手机上日志栏占屏幕 30% —— 要把 x=12% 的热点挪出这条，得挪到 38%，
那就指到完全不相干的景物上了（"热点乱跑"）。所以"挪"只做了小幅微调（既让开一部分、又不失准），
真正保证"永远看得见、点得到"的是第 1 条。

探针还顺手加了两项体检：**同屏热点互压**（排列时最容易踩的坑）和**点击穿透**
（elementFromPoint 能不能命中热点）——现在两项都是 0 报警。

# 洞穴熊：第 30 天起才出现（作者 2026-09-15）

先回答"洞穴熊只会在移动中拦路吗"——**不是**，它有两处出现：

# 珍珠之心爆率 + 神弓不掉耐久（作者 2026-09-15）

## 1. 珍珠之心的源能水晶爆率：30% → **50%**

`atl_pearlheart` 的产出里 `energyCrystal` 的 `chance` 从 0.3 改成 0.5（其余产出不动）。

## 2. 「神弓怎么不掉耐久？」——远程武器**从来没扣过耐久**

**根因**（跟"邮件里领的"没关系）：

```js
// 近战：命中后 drainWeapon() → 磨损"本轮出手的那把"
// 远程：只调 ammoConsume() 扣箭/子弹 —— 弓和手枪的本体永远不磨损
```

`drainWeapon()` 只有近战会调；远程开火那两条路径（普通射击、弓先手那几箭）都只走 `ammoConsume()`。
所以**所有远程武器都是"永不磨损"**：普通弓、神弓、手枪都一样。

**改法**：

- 把 `drainWeapon()` 里的磨损逻辑抽成 `drainEquipSlot(slot)`（近战/远程共用同一份规则：
  按实例扣、用坏就移除、命名的武器保留不消失、坏了自动换背包里的备用武器）。
- 新增 `equippedRangedSlot()`（口径与 `rangedWeapon()` 一致：主手优先），
  在 `ammoConsume()` 里"每开一枪/射一箭"磨损一次 —— 开火才磨，落空不磨（跟近战一致）。

回归实测：弓耐久 70 → 64（打 6 次）、箭 30 → 24 ✓。神弓（50 耐久）现在会正常磨损，
而"邮件里存着的那把带着剩余耐久回来"这套逻辑也终于有意义了。

## 3. 手枪 / 神弓 的耐久对调（作者 2026-09-15）

`DURA` 里两者互换：**神弓 50 → 120**、**手枪 120 → 50**（其余武器不变）。
因为第 2 条已经让远程武器真的磨损，所以这个数值现在直接决定"能开多少枪/射多少箭"。
回归里把原来那条"神弓耐久 50"的断言改成了 120，并补了一条"手枪耐久 50"。

   以后玩家再说"闪退"，把安全模式里那行字发我就够了。
3. **渲染兜底**：`render()` 包了 try/catch，出错不再整屏空白，改为底部一条提示条（并记录报错）。
   新增导出 `Game.restoreBackupSave()`：把上次保存前的滚动备份 `guyuyizhang_save_bak` 当主档读回来。

实测（`开发工具\检查\_debug_safemode.js`）：正常启动 → `boot.ok=true`；伪造崩溃后重载 → 安全模式自动弹出且带出
`TypeError: fake boom`；点「用备份存档打开」→ 成功进入游戏 ✓。

## 2026-09-17：结局结算入口 + "点不了去山顶"

作者问："点击结局按钮会有结算画面和结算文字吗，有人反馈点不了去山顶。"
实测（新探针 `开发工具\检查\_debug_peak.js`，一次跑完两个问题）：

### ① 结局按钮**没有**结算画面 —— 是真 bug，已修

点「祭坛仪式（结局·秘辛）」原来只做两件事：写一行日志、给 `flags.ended_C` 打勾。
**结算画面（`#ending-screen`）根本不会出现**，只有死亡时才会弹。
根因：`settleEnding()`（写 `S.ending` → 触发 `onEnding` → 弹结局画面 + 结算文字）**在整个项目里没有任何界面调用**，
是条走不到的路；`checkEndingActions()` 末尾那句注释"已达成但未结算的结局：提供结算动作"也没兑现。
附带问题：结局按钮达成后不消失，材料一直齐着就一直点得到，点第二次只打印"祭坛的光芒已经黯淡"。

改法（三处）：

- `checkEndingActions()`：A/B/C/S/S2 五个"触发"按钮加上 `!flags.ended_X`（达成后消失）；
  末尾补上真正的**结算按钮** —— `结算 · 结局「秘辛」`，一局里每个结局只在"未结算"时出现一次。
- `doEnding()` 成功后调 `askSettleEnding()`：弹「结局达成 · 秘辛」，两个选项
  **观看结算画面 / 继续探索**（不再让玩家猜）。两条路都保留，继续玩不会丢进度。
- `settleEnding()` 落一枚 `flags.settled_X`：防"结算 → 留在岛上 → 再结算"刷魂点
  （`metaSettle()` 本身也防重复，这里是第二道）。

实测结果：点结局按钮 → 「结局达成 · 秘辛」→ 观看结算画面 → 结局画面出现（标题/第 N 天/插画/结局文字/诗句/

重看结算画面不再发魂点（525 → 525）。截图：`开发工具\检查\_out\ending_screen.png`。

### ② "点不了去山顶" —— 半个真问题，已修

实测四种情况：

| 情况 | 改前玩家看到什么 | 改后 |

### 改法

- `ITEMS.divineBow` 加 `keepBroken:1`，`drainEquipSlot()` 里 `keep = 已命名 || 物品.keepBroken`：
  耐久归零**保留在背包**、自动卸下，日志写"神弓损坏了（限时绝版物品不会消失），回营地用磨刀石修补后再用"。
- 修补材料单列：`REPAIR_MATS.divineBow = 秘银锭×1`（原来走 `['stone',2]` 兜底）。
- 自动换手会**跳过耐久 0 的武器**（以前可能把刚打坏的又顶回主手，一装就又"坏"一次）。
- 磨刀石面板按当前主手武器**实时显示**修补材料（以前不管修什么都写"耗 石头×2"）。
- 顺手：耐久满时点"修补"不再白吃材料（以前照收）。
- 说明与攻略文案同步（耐久 120、坏了不消失、攻略页加上"限时绝版的神弓耐久归零也不会消失"）。

## 2026-09-18（六）：音效与配乐重做（玩家反馈"叮铃太频繁、有些音效拉胯"）

先把"听力问题"变成可测的数字：新探针 `开发工具\检查\_debug_audio.js` 用一个假 AudioContext
记录每一次发声（频率/波形/时长），再用假时钟快进跑完 **2 分钟**（白天营地 + 洞穴夜）和一轮玩家操作
（20 条系统日志 + 拾取/交易/战斗/点击），统计"叮铃区（>2500Hz）"次数与刺耳波形占比。

### 改前实测（就是玩家听到的那版）

| 指标 | 改前 |
| --- | --- |
| 发声总次数（2 分钟） | 315 |
| 高频 >1200Hz 占比 | 79% |
| **叮铃区 >2500Hz** | **166 次** |
| 刺耳波形（方波/锯齿） | 28 次（9%） |

三处元凶：
1. **系统日志有 40% 概率放"拾取铃"**（660→880Hz 双音）——采集/制作/赶路都写系统日志，所以一直在叮；
2. **洞穴水滴每 0.9 秒一滴**（1400~2400Hz 带下滑音）——就是"叮、叮、叮"；
3. **夜里虫鸣 0.4~0.9 秒一次、3400Hz**——像耳鸣。

### 改了什么

- 总线：音乐/音效各加一道"温暖低通"（2kHz / 7kHz），磨掉高频尖角。
- 日志提示音：40% → **8%**，并换成 300Hz 的一声闷音（不再抢耳朵）。
- 水滴：0.9 秒 → **随机 4.5~11 秒**，音高 900~1500Hz、音量降到 1/3。
- 虫鸣：0.4~0.9 秒 → **1.8~5.2 秒**，音高 3400→2300，音量减半；偶尔只叫一声。
- 篝火噼啪：间隔 260→420ms，音量/频率都降；鸟鸣音高压到 2000~2900Hz。
- 界面"咔哒"：**方波 → 三角波**（还是有棱有角，但不"塑料"），音量 0.085→0.06。
- 拾取/获得/交易：**降八度 + 换柔和波形**（拾取从 660→880 改成 540→405 往下走）。
- 战斗/死亡音：方波、锯齿全部换成三角波；连 boss 音乐的低音床也从 sawtooth/square 改成 triangle。
- 配乐：音符间隔 4.5s → **6s**，音量降一档，低八度伴音概率 35%→65%，每句再加"根音+五度"的 10 秒和声垫 → 更厚更暖、不再一句接一句。

### 改后实测

| 指标 | 改前 → 改后 |
| --- | --- |
| 发声总次数 | 315 → **119**（-62%） |
| 高频 >1200Hz 占比 | 79% → **38%** |
| **叮铃区 >2500Hz** | 166 → **16**（-90%） |
| 刺耳波形 | 28 → **0** |

剩下的 16 次叮铃区基本都是"界面咔哒"本身（点击声就该脆），属于设计内。

**自检**：回归 **827 项全绿**（新增 7 条：日志不再叮、水滴/虫鸣节奏、无方波锯齿、温暖低通、配乐呼吸感、音效降八度）；
`_debug_audio.js` 前后对比数据在上面；公告自检 34 项全绿。**我本人听不到声音**，最终听感要作者自己试。

## 2026-09-18（七）：玩家反馈四条（材料/精算/弓先手吞操作/工具耐久扣错）

主人转述（带截图）："材料扣的有问题，精加工实际没省下材料，木炭扣3个，没有退回木材"、
"装备弓不给我逃跑"、"装备神弓时另一件装备不生效，只能射箭"、"扣耐久扣的不是装备上去的"。

四条逐一实测，**都是真 bug**：

1. **制造界面显示的是"配方原价"，实际按技能加成扣**
   截图里"烧木炭 木材 120/2"，但实际扣 3 —— 因为学了「精工细作」（材料 +30%：2×1.3 → 3）。
   → 界面改成显示 `Game.craftIn(r)`（真实消耗）。顺带澄清：**省料的是「流水线」（-50%）**，
   「精工细作」是"+30% 材料换 +30% 耐久"，两者互斥 —— 界面现在直接显示 3，不会再误会。
2. **【精算】退款其实一直在生效**：实测 29/29 次都真的加回了材料（净消耗 = 成本-1）。
   之前看着像没退，是因为**显示基准价错了**（显示 2、实际扣 3、退 1 → 看着"没退"）。现在基准对齐后就清楚了。
3. **弓/枪的先手箭会"吃掉"玩家那一次操作** ← 这条最严重，正好对应两条反馈：
   老写法是"每次点操作 → 先射一箭 → 直接 return"，于是装备弓/神弓时**逃跑、防御、道具点了全没反应**
   （"装备弓不给我逃跑"），副手近战也永远轮不到（"只能射箭"）。
   → 改成**开局当场把 2~3 箭打完**（含神弓的"第一次命中必会心"），之后每一次点击都正常结算。
   实测：装弓 + 副手铁剑 → 点「攻击」用副手砍（副手掉耐久）、点「逃跑」能跑掉、弓的耐久在开局就掉完。
4. **采集磨损扣的不是"装备上去的那把"**：`bestToolTier()` 按**工具栏**算等级，`drainTool()` 却从**整个背包**
   挑等级最高的扣 —— 所以"栏里装石斧、背包放钢斧"时扣的是背包钢斧。
   → 改成**扣工具栏里那把**（栏里没有才回退到背包）。实测：石斧 25→24，钢斧 77 不动。
